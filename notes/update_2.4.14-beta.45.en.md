# Tuff v2.4.14-beta.45 Release Notes

## Summary Notes

- The first-run wizard no longer treats "follow the system" as a choice the user already made: on an English macOS it answers 简体中文, renders in the language it is asking about, and returning from the language list no longer rewrites the preference behind the user's back — the shortcut-conflict line on its last page is gone as well.
- Two flows asking for one plugin's permissions show one card, and that card's identity is now the plugin id plus the permission set rather than the copy — so a *different* plugin with the same display name can no longer read back a decision the user made about the first one.
- The install transport deadline is no longer a flat 3 minutes: it is the sum of the download budget, the 120s confirmation budget and the 60s unpack budget, so it can no longer report "install failed" while the user is still reading the permission card, and a 14 MB package is no longer killed at 30s with `NETWORK_TIMEOUT` on an ordinary connection.
- The `plugin:api:install` event derives its deadline from the same budgets, and both install events have their deadline sources written into the channel contract.
- Home's assistant recommendations are opt-in: a new `homeRecommendations` setting defaults to off, so the opening greeting and the suggestion cards only appear when explicitly enabled, and any config saved before the key existed reads as off.

## What's Changed

- First-run language: the wizard answers with `BOOT_LANGUAGE_PREFERENCE` (the product default, `zh-CN`) instead of treating the system language as the user's choice — "never chose" and "chose to follow the system" are byte-for-byte identical in the settings, so the persisted `beginner.init` flag ("has the wizard been completed") is what distinguishes them; a user who already chose and reopens the wizard still starts on their own choice. The card shows the language that is about to be applied, the `跟随系统` tag appears only while that answer really is the system language, and a new `previewPendingLanguage()` renders the step in the language it is asking about (picking from the list already switched the UI live; without it, first run on an English system read as English copy above a 简体中文 card). Returning from the list now only closes it — the old code called `setFollowSystemLanguage(true)` there and silently rewrote the preference.
- Wizard's last page: the shortcut-conflict line (`beginner.done.shortcut.conflictHint`) is gone — the element and its style, both locale entries, the case that pinned it and the references in the global-shortcut contract, which now records the removal.
- Permission card: one question about one plugin now shows one card (the install confirmation and the enable-time gate arrive over different transports and used to build one each, counting down separately, with the second still standing after the first was answered). The merge key moved from `title\0message` to `permissionRequestIdentity(pluginId, permissionIds)` (deduplicated, sorted, order-independent): both askers were always asking about the same plugin id and the same `missing.required` set (`getMissingPermissions` on each side), so the coalescing still fires while no longer depending on the two sides agreeing on a display name (the install confirmation takes `clientMetadata.pluginName`, the gate takes the manifest's `name`). Under the old text key, a different plugin with the same display name could read back a decision made about the first one — and the gate grants `request.pluginId` from exactly that decision.
- Install budgets: `packages/utils/plugin/install-budgets.ts` is now the single source — the download budget scales with the registry's advertised size at a deliberately pessimistic 50 KB/s, floored at 30s and capped at 10 minutes; the confirmation budget is 120s (the renderer's card auto-denies at that point, which bounds the main process's wait for the user); unpack, signature verification and registration get 60s; and the `plugin:install-source` transport deadline is their sum. The flat 3 minutes used to expire while the user was still reading the card, reporting an install as failed after its 14 MB download had already succeeded. Providers stop carrying their own copies of those constants.
- Home recommendations: `app-settings` gains `homeRecommendations`, defaulting to `false` (Beta) — a blank Home conversation no longer shows the opening greeting or the suggestion cards unless it is explicitly enabled, and a config saved before the key existed reads as off. `HomePage.vue` and 设置 · 插件与工具 are wired to it, covered by `SettingTools.home-recommendations.test.ts`.
- Channel: this beta merges `origin/master` into `stage` before it is cut, so the changes above travel into the beta channel with this build and `master` no longer runs ahead of what testers have.
