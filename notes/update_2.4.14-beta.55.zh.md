# Tuff v2.4.14-beta.55 更新说明

## 摘要

- Browser 插件支持复制网址直开、可配置搜索引擎和微博热搜入口，一次回车即可执行。
- 输入目录路径后，CoreBox 优先推荐默认终端、已安装终端和 Finder 操作。
- 推荐与使用统计只记录已接受的执行，统一常用推荐、曝光记录和排序依据。
- 图片预览保留透明背景，改善缩略图、快捷操作和动作面板的悬停反馈。
- 原生 OCR 移至独立进程，渲染层平台标识统一为 darwin、win32 和 linux。
- TuffEx 新增 StreamText、StreamElement 和内容驱动的 CodeStream，并同步文档示例。

## 变更内容

- Browser 1.1.0 从 CoreBox 查询输入识别复制的网址，按本机可用浏览器生成直接打开入口。
- 网页搜索内置 Google、Bing、DuckDuckGo 和百度，支持自定义 {query} 模板、默认引擎与启停配置。
- 微博热搜及自定义快捷入口可按关键词直达；搜索设置保存后立即同步，不把文件名和路径当作网页查询。
- 新增 SDK API 标记 261001，包含初始化期间 SDK 调用、单次执行文本保留和浏览器发现修复；原有受支持标记继续可用。
- 目录推荐支持默认终端、Ghostty、iTerm2 等本机终端与 Finder，执行时校验目录和应用仍可用，并排在普通文件结果前。
- 插件设置通信等待真实生命周期处理完成后才确认，处理失败时返回错误，不提前报告同步成功。
- CoreBox 执行记录、使用统计与推荐评分共用接受执行的边界，新增使用事件迁移与隐私清理支持。
- 空态推荐加入默认设置入口，统一插件推荐来源、曝光记录及推荐依据的展示。
- 缩略图与文件图标缓存保留透明度，图片预览增加快捷操作，动作菜单加入连续悬停高亮。
- 应用列表与详情复用统一行组件；FlatInput 调用方迁移至 TxInput。
- 原生 OCR 在可终止的独立进程中执行，避免识别工作占用 Electron 主进程。
- 初始化与 body 平台标识使用相同规则；窗口角色和 arm64 等架构标识保持独立。
- TuffEx 流式文本支持增量显示、节奏控制与插槽，StreamElement 支持结构化内容，CodeStream 支持内容驱动模式。
- TuffEx 弹窗、分页、选择器、图片画廊和分隔布局改善细节交互；无操作的状态徽标保持被动语义。
- 官网文档导航使用单一移动高亮，画廊按实际示例组织，新增流式组件示例并统一 Tuff 名称。

- Axios 升级至 1.20.0，brace-expansion 保持原主版本并升级至修复递归耗尽和 ReDoS 的安全补丁版本。

## 破坏性变更

- Browser 1.1.0 要求 sdkapi 261001，需先升级至本版或后续兼容客户端；beta.54 及更早客户端会拒绝启用。
- TuffEx 移除 FlatInput 导出和相关旧入口，外部调用方需改用 TxInput。
