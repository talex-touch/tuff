00

基线审计：先找到真正的常驻工作

启动成功并不等于空闲。基线包在 CoreBox 隐藏时仍启动 Pi utility process，性能遥测保留一条 120Hz RAF 链；搜索 Worker 还从错误的 chunks 目录启动。

OBSERVED
Before
控制面初始化与重型执行面绑定

AiCliOrchestrator.initialize() 直接等待 runtimeHost.start()；隐藏 BrowserWindow 内 document.hidden === false，仅靠 Page Visibility 无法停表。

→
Audit output
拆成 3 个独立根因

进程生命周期、渲染调度生命周期、原生窗口可见性。打包搜索故障另作为运行闭包问题处理，不混成一个“CPU 优化”。

直接证据

  • 基线日志：Pi runtime utility process spawned 出现在启动健康检查附近。
  • 隐藏 CoreBox 1 秒探针：性能模块发起 120 次 RAF，请求来自两条独立循环。
  • 基线 Worker：请求 out/main/chunks/search-index-worker.js，随后 MODULE_NOT_FOUND 与 unhandled rejection。
  • 基线进程组 5 次采样中位数：8 个进程、1508.75 MiB RSS、80.7% CPU。

测量边界

  • macOS arm64、unsigned packaged app。
  • 基线和最终版均使用全新隔离 profile。
  • CDP 已连接；采样为 5 次、间隔 1 秒。
  • CPU / RSS 是短窗口诊断，不是长期基准。
关键判断：Electron 隐藏 BrowserWindow 的 renderer 仍可报告页面可见。若只监听 visibilitychange，后台 CoreBox 的 RAF 所有权不会自动消失。
01

Pi runtime：控制面常驻，执行面按需启动

保留工具注册、profile、会话恢复和审批控制面；删除初始化阶段的 utility process 启动。真正执行 run 时，由 PiAgentRuntimeHost.execute() 调用 start()。

VERIFIED
Before
initialize() → runtimeHost.start()

即使用户从不调用 AI，启动也创建名为 Tuff Pi Agent Runtime 的 utility process。

→
After
execute() → start()

初始化日志改为 control plane initialized；执行前仍经过 app-ready、worker path 和 restricted environment 检查。

实现动作

  • 移除 orchestrator 初始化中的 eager await this.runtimeHost.start()。
  • 不引入备用 runtime、不弱化审批和预算边界。
  • 保持 execute() 内 await this.start()，并复用并发 start promise。
  • 停止路径仍负责 cancel active runs、kill child 与 reject pending readiness。

涉及文件

src/main/modules/ai/ai-cli-orchestrator.ts src/main/modules/ai/pi-agent-runtime-host.ts src/main/modules/ai/pi-agent-runtime-host.test.ts
本机结果：最终包启动日志没有 Pi spawn；相同采样条件下进程数中位数 8 → 7。75 个聚焦契约测试包含 orchestrator、Pi host、可见性、遥测、CoreBox IPC 和 Worker resolver。
02

遥测 RAF：从“递归自驱动”改成“单一所有权”

性能遥测现在只允许一个 RAF handle；renderer inactive 或 document hidden 时同步 cancel、清空 frame baseline，并在恢复时重新基准，避免把休眠间隔误记为 jank。

MEASURED
Before
重复 start 可产生多条递归链

循环内部无 owner handle；隐藏 BrowserWindow 仍请求 frame。本机同页观测为 120 requests / second。

→
After
一个 handle，明确 start / stop / rebase

rafId !== null 拒绝重入；inactive 时 cancel；active 时从新的 performance.now() 开始。

行为契约

  • Telemetry disabled：不建立 observer、polling 或 RAF。
  • Native renderer inactive：取消 RAF 并触发一次 buffer flush。
  • Page hidden：同样取消 RAF；Page visible 只在 native active 时恢复。
  • 重复初始化：started gate 保证无第二套 listener / polling。

涉及文件

renderer/src/modules/telemetry/performance.ts renderer/src/modules/telemetry/renderer-activity.ts renderer/src/modules/telemetry/performance.test.ts
确定性探针：基线 120 → 最终 0 次性能遥测 RAF / 1 秒，两个页面都报告 document.hidden === false。这个差值来自 native activity gate，而非浏览器自动节流。
03

原生可见性握手：main process 是事实源

renderer 先安装 push listener，再向 main 查询当前 BrowserWindow 可见性；请求版本防止迟到响应覆盖更新鲜的 push。收到 native 信号后，document visibility 只保留为降级路径。

TESTED
Before
useDocumentVisibility() 代替窗口状态

页面可见与 BrowserWindow 可见不是同一状态；renderer reload 后也可能错过一次 show / hide push。

→
After
query + push + race version

core-box:ui:get-visibility 从 BrowserWindow.isVisible() 回答；dom-ready 与 did-finish-load 都补发状态。

竞争处理顺序

  • 注册 CoreBoxEvents.ui.trigger listener。
  • 立即把 document state 作为暂时 fallback 注入 activity bus。
  • 记录 request version，向 main 请求 native state。
  • 若期间收到 push，版本递增；迟到 query response 被丢弃。
  • 建立 native truth 后，不再让 document watcher 覆盖它。

涉及文件

core-box/ipc.ts core-box/window.ts hooks/useVisibility.ts transport/events/types/core-box.ts
非目标：没有把通用 document visibility 删除。它仍服务 main renderer 与 transport 不可用时的 fallback；只是 CoreBox 一旦拿到 native signal，就不再混用两个事实源。

Deep evaluation · wave 2

重复启动、进程归因、145 次搜索与句柄压力

第二轮继续使用 canonical macOS arm64 包和隔离 profile。启动样本 n=5 + 5；进程采样覆盖可见设置页、后台、搜索负载、Worker 关闭后的稳定状态，以及运行 50+ 分钟后的文件描述符快照。

Hot / cold startup

  • Hot 5 轮：P50 430 ms，P95 450 ms，范围 419–450 ms；renderer-ready P50 351 ms。
  • Cold 5 轮：P50 442 ms，P95 471 ms，范围 425–471 ms；renderer-ready P50 338 ms。
  • Cold 比 hot 的 startup-health 中位数慢 12 ms；当前样本量不足以推断长期分布。
  • Hot 慢模块均值：PrivacyLifecycle 47.4 ms、NativeCapabilities 45.2 ms、CoreBox 42.2 ms、Database 32.0 ms。
  • Cold 慢模块均值：Database 51.2 ms、PrivacyLifecycle 43.8 ms、CoreBox 41.6 ms、Storage 32.6 ms。

为什么 10 轮都被 gate 判为 FAIL

  • 10 轮均为 0 ERROR、1 WARN。
  • 唯一告警：Native screenshot protocol carrier unavailable reason=binding-unavailable。
  • 因此 benchmark gate 的 blocking issue 全部是 startup_logs_nonzero，不是启动超时或 Worker 崩溃。
  • 这是 standing audit 已记录的 packaged native screenshot closure 风险；报告不抑制该警告。

Remediation · wave 3 · 2026-08-04

renderer、事务与 watcher 一起收口

第三轮沿用 canonical macOS arm64 包和同一 disposable profile。数据库修复在自然 10 分钟 mdls tick 上验证；最终平台分流包随后复用该 profile 验证总 FD、搜索与隐藏回收。

可选 renderer 按需拥有

  • fresh start 未创建 CoreBox、DivisionBox 或 MetaOverlay renderer；日志明确显示 DivisionBox pool 为 on-demand。
  • CoreBox 首次 show 后创建，Safari 与 Calculator 均返回真实应用结果；20 次 25 ms 快速输入最终稳定在 Calculator，未见 stale result。
  • MetaOverlay 连续 3 轮 show → action → hide 均通过；每轮按 is-visible 等待 400–500 ms 完成按需 renderer 装载，action 返回 success，hide 后均回到不可见。
  • immediate hide 后 60 秒出现 Destroyed hidden CoreBox after idle timeout；进程集合回到 main、GPU、network、main renderer 与 crashpad。

mdls / reconcile 连接有界

  • App metadata 每 50 条复用一个 LibSQL transaction；146 个 mdls 更新总落库 22 ms。
  • Reconcile upserts / deletes 由 production store adapter 进入 provider-level writer batch，不再 146 个 delta 各开一次 transaction。
  • 自然 mdls tick 后 database.db numeric FDs 为 11，旧路径同规模为 148；没有依赖 monkey patch 或 forced GC。

macOS watcher 回到 FSEvents

  • Chokidar 4 已移除 bundled FSEvents，递归根会对每个发现文件建立 watcher；本机 Pictures / Music / Movies 立即把总 FD 推到 400+。
  • Windows / Linux 保持 Chokidar 4；macOS 通过 package alias 选择 Chokidar 3.6 + packaged fsevents.node。
  • 最终 packaged start 总 numeric FDs 为 166；连接 CDP、打开 CoreBox 并完成搜索后为 192，均低于 256 内部阈值。

设置页仍高，但不再无上限

  • 可见页 2 秒内观测 49 次 WebGL clear，即 24.5 Hz；低于 30 Hz cap。
  • 同一 renderer 收到 native window hide 后 2 秒内 0 次 draw。
  • 可见设置页进程组 CPU P50 59.7%，较 wave 2 的 77.0% 下降 17.3 pp；隐藏稳定态 P50 0.75%。

No hidden debt

剩余风险

修复目标是生命周期与打包闭包，不把邻近风险顺手扩成新项目。

High · measured

设置页可见时 GPU 占用仍高

30 Hz cap 将进程组 CPU P50 从 wave 2 的 77.0% 降到 59.7%，WebGL 实测 24.5 Hz，native hide 后为 0 draws；但可见页接近 60% 仍不可称为轻量。

Medium · measured

后台内存改善但仍重

可选 renderer 按需创建并由 TTL 回收后，隐藏设置页稳定态从 1172.89 MiB 降到 790.89 MiB；关闭 main renderer 后为 527.95 MiB。Electron 基础成本仍显著高于 native launcher 的资源心智。

Medium · soak

FD 已回阈值内，仍需长时回归

provider batching 与 macOS FSEvents 将总 numeric FDs 从 775 降到无 CDP 的 166，146-app mdls 后 primary DB FDs 从 148 降到 11。当前通过 10+ 分钟与搜索 / TTL 验证；仍需 CI 或 nightly 长时 soak 防回归。

Medium · scope

竞品资源未同机

四个竞品当前未安装。本报告只比较公开能力；任何资源结论都必须在同架构、同 settling window、同操作脚本下重测。
