# File Watcher and Scoped Reconciliation Contracts (main process)

These contracts define the deep macOS file watcher boundary and its indexed-file consumer. They apply to `FileSystemWatcherModule`, `MacOSFileWatcher`, `IndexedSourceEventRouter`, and the file provider's subtree reconciliation path.

## 1. Deep macOS registration is event-only

The macOS watcher used for `FILE_SCAN_MAX_DEPTH` roots registers an FSEvents stream against the canonical root without recursively enumerating existing descendants. Shallow application watches and non-macOS watchers retain their existing Chokidar selection. The native module loads `fsevents` lazily and treats an unavailable optional binary as an explicit registration error. The dynamic import must remain variable-driven so Windows/Linux typechecks do not require a Darwin-only optional dependency.

`fsevents` is a CommonJS wrapper around a native addon and MUST stay external in the main-process Electron Vite build. If Rollup bundles it, the addon becomes an ESM namespace and `flags.SinceNow` is undefined at runtime even though source-level tests pass. Keep it in `externalizeDepsPlugin.include`; Darwin packaging must fail before build when the backend cannot load and after pack when `app.asar.unpacked/node_modules/fsevents/fsevents.node` is absent. Verify the built output retains `import(moduleName)` plus one real Electron registration/add/delete smoke.

The application may still schedule its independent initial index scan. That scan is separate from watcher registration and must not be used to justify recursive work performed by the watcher constructor or `add` method.

## 1a. Full-scan enumeration may use bundled fd

The independent snapshot scan may use the application-bundled `fd` binary. Production resolution never consults PATH and never downloads a binary. The command is fixed to files, hidden/no-ignore input, absolute NUL output, no colour, no symlink following, the shared maximum depth and one fd search thread, plus one `--exclude` per glob from `fileFilterService.getTraversalPruneGlobs(root)`. Those globs name only directories the traversal policy rejects in every context (hidden names, bundles, context-free development and cache names, and the home-anchored system and toolchain folders when the root is a home directory), so pruning never changes the admitted set; on 2026-10-20 it cut one workspace root from 1,892,378 enumerated paths to 110,257 with the same 70,464 admitted files. The backend never adds a glob of its own. Tuff remains the authority for roots, exclusions, conditional project-directory rules, NFC path normalization and final file admission, and still applies them to every path fd returns.

stdout is consumed incrementally. At most two metadata checks run concurrently, and the existing 500-record batch acknowledgement backpressures the pipe. Spawn failure, unsupported platform package or non-zero exit restarts the same root with the legacy walker. A partial fd stream never writes root completion; repeated records from the fallback converge through existing upserts. Abort kills the child and waits for its pipes and exit. Runtime diagnostics state the fallback once without logging user paths.

The platform binary lives in `@prebuilt-binary/fd@10.4.2`, is made executable during install and again in `afterPack` before signing, and is unpacked from asar. Runtime resolution must map `app.asar` to `app.asar.unpacked` idempotently. The file-scan worker imports the worker-safe traversal policy and native-binary path helper directly; importing the Electron-facing `files/utils.ts` makes the packaged worker fail before fd can start. `afterPack` also requires both upstream license texts. macOS x64 has no package at this version and therefore uses the legacy walker explicitly.

## 2. Logical paths remain stable

The watcher canonicalizes the native stream root only for event subscription. It emits the configured logical root and logical descendant paths so indexed identity remains stable across aliases such as `/var` and `/private/var`. A native path outside the canonical root, an excluded path, or a path deeper than the configured depth is ignored.

The watcher applies the existing traversal exclusion predicate to every path and its ancestors. It does not follow child symlinks into a second configured scope. A symlink event invalidates the smallest affected logical subtree; the provider then uses `lstat`, refuses a symlink as a scan root or file record, and treats any existing symlink row as stale rather than following its target.

## 3. File events are bounded and settled

File `add`, `change`, and `unlink` events are emitted only after bounded metadata inspection. At most four metadata checks run concurrently and at most 1,024 paths remain pending. Changed files use the existing 500 ms write-settle behavior with a bounded 30 second escape hatch. Overflow emits one root invalidation and resumes delivery after the invalidation has been queued.

The watcher does not poll idle paths. A metadata error other than `ENOENT` or `ENOTDIR` is emitted as an error and does not become a deletion. Native event loss, `MustScanSubDirs`, root changes, and directory changes are invalidations rather than ordinary file events.

## 4. Invalidations reconcile one admitted subtree

`FILE_WATCH_SUBTREE_INVALIDATED` carries `path`, `rootPath`, and one of `directory-change`, `event-loss`, `overflow`, or `symlink-change`. The router validates containment, coalesces descendants under an ancestor, bounds pending scopes, and routes each resulting scope to the file indexed source with reason `file-watch-subtree`.

Each scope logs one INFO line, `Reconciling invalidated file watch subtree`, as its turn in the chain starts: `reason` (the invalidation that opened the scope), `atWatchRoot`, `depth` below the watch root, and `coalesced` (the watcher invalidations folded into the scope: descendants an ancestor replaced, later arrivals it covered, and everything pending when more than 128 scopes under one root collapse into the root with reason `overflow`). The line carries no path. A whole-root pass and a one-folder pass cost very differently, and before the line nothing in the log said which of `overflow`, `event-loss`, `symlink-change` or `directory-change` had started one. The counts are bookkeeping for this line only; they never decide what is scheduled (`indexed-source-event-router.reconcile-log.test.ts`).

The provider branch for this reason is the only scoped reconciliation path. It fixes a high-water database id before streaming scan batches, writes through the existing incremental mutation service, and pages existing file rows through that id for disappearance cleanup. The scope matches as a BINARY path range (the exact path or its `/`-terminated prefix), never `LIKE`, which cannot use `files_path_unique`; the pages retain `type = 'file'`. Permission and I/O errors propagate; only `ENOENT` and `ENOTDIR` mean that a path is absent, while a final symlink is deliberately non-indexable.

The high-water read and every page go through the search-index read worker (`SearchIndexService.readFileSubtreeBound` and `readFileSubtreePage`, implemented in `file-subtree-reads.ts`), never the main-thread connection. The bound is index-only and carries no `type` test, so it may be looser than the exact largest id but never tighter. A scope with at most 16,384 path-index entries is bounded by its own largest id and paged through `files_path_unique`. A larger scope is bounded by the table's largest id (ids never repeat, so rows inserted afterwards still exceed it) and paged by a rowid walk. Both page plans are pinned in the SQL (`INDEXED BY` / `NOT INDEXED`) and asserted by `file-subtree-reads.test.ts`, because the index has no table statistics and an unpinned planner walks the rowid range of a small scope, testing most of the table. The retired bound read `type = 'file' AND <scope> ORDER BY id DESC LIMIT 1` and cost 6.7 s of blocked event loop on a cold 6.4 GB index for a home-directory scope, and the unpinned pages of a 4.3k-entry screenshot folder took 5.4 s per sweep by rowid walk against 0.15 s through the path index (2026-10-30, cold APFS clone).

Those reads share the reader with search and can fail for reasons that say nothing about the query: the reader is rebuilding or cooling down after repeated failures (`SEARCH_INDEX_READ_WORKER_UNAVAILABLE`), its queue is full (`SEARCH_INDEX_READ_QUEUE_FULL`), or a read timed out (`SEARCH_INDEX_READ_TIMEOUT`); `isTransientSubtreeReadError` names exactly these. Such a failure must not cost the folder its new files, so `FileWatchSubtreeService` treats it as a deferred sweep, not a failed scope: when the bound cannot be read, the scan and the writes still run and no sweep is opened; when a page cannot be read, the sweep stays open at its saved cursor. Either way the result reports `deferred` (file maintenance is scheduled) and the next reconcile of the scope finishes the cleanup. A failure after the run was aborted, and any other read failure, still fails the scope.

Records are compared before they are leased. `FileWatchSubtreeService` hands each scan batch (at most 64 records) to `FileProviderSubtreePersistService`, which admits the records, reads their rows by path in one query (`+type = 'file' AND path IN (…)`, planned as `SEARCH files USING INDEX files_path_unique (path=?)`) and runs the incremental write planner (mtime and ctime within 1 s, size, extension, name) outside any lease. Only the records the planner reports as new or changed take a mutation lease, ten per slice, and each slice compares again under the lease because the rows may have moved; a slice that finds nothing left commits nothing. A record the index already holds never reaches the idle gate, the lease queue, or the enrichment resume that follows a base commit. Before this, every ten scanned records took a slice whether or not anything had changed: the slice waits until no search ran in the last 2 s and no app task or interactive write is active (polled every 100 ms), queues FIFO behind every other writer (an enrichment round holds one lease per 200-row page), and resumed enrichment after committing nothing, so walking an unchanged folder of 4.3k files paid about 430 of those. The 8 s scope budget of the hot catch-up counts all of that waiting, and the walk could spend it before reaching a new file. The probe read took 119 ms cold in 68 queries and 6 ms warm on the 4,294-file Pictures folder of a cold 6.4 GB APFS clone (2026-10-31), the same cold total as the 430 ten-path reads it replaces (118 ms); the cost that went away is the gate and the lease, not the read. Covered by `file-provider-subtree-persist-service.test.ts`.

Scoped reconciliation preserves the configured watch-root depth when a nested directory is scanned, passes cancellation through every scan/read/write/delete boundary, and never falls back to provider-wide indexing for an ordinary directory event. Batch sizes, page sizes, existence checks, and queued scopes remain bounded.

## 4a. Startup catches up the hot directories

FSEvents delivers nothing for the time the app was not running and a boot never forces a scan, so a screenshot or download that landed while the app was down or busy stayed unsearchable until a whole-home reconcile reached it. Once the search index worker is ready and the watchers are registered, and before file maintenance is scheduled, `FileProviderBootPassService.maybeRunHotCatchup()` runs `FileProviderHotCatchupService` once per boot. Planning, lane and reconcile errors are contained: a failure is one warning and never rejects the startup chain.

The plan holds at most 12 scopes, each strictly below a watch root: the existing Desktop, Downloads, Documents and Pictures folders of the home directory, plus the parent directories of the 200 newest indexed files created in the last 30 days (`getRecentlyCreatedFiles`, backed by `idx_files_is_dir_ctime`). An unnamed direct child of the home directory (`~/Workspace`, `~/Library`) is not hot evidence and is dropped, and a directory that stale exclusion or a linked worktree would refuse is not admitted. The four named folders keep their slots; the rest are ordered newest first by directory mtime or file creation time. A scope is recursive, so an ancestor walks everything below it again, yet nothing is dropped for being nested: a folder below another planned scope runs first (deepest first) and the ancestor keeps its own place in the order. The newest evidence usually sits in a small folder (a screenshot folder), while Pictures or Documents can be large enough to spend the whole 8 s budget, and a folder left to that walk would not be caught up at all. Each scope is an ordinary `file-watch-subtree` reconcile run through `IndexedSourceEventRouter.withHotSubtreeLane`: one exclusive turn of the chain that serialises subtree reconciles, taken ahead of every scope that has not started yet and never interrupting the running one; `unsubscribe()` aborts it. The run stops at 20 s in total, aborts a scope at 8 s (`timedOut`), and stops within 250 ms of shutdown. A whole-source reconcile holding the source's run gate fails a hot scope (`failed`). A scope that failed, timed out, or was never reached before the 20 s ran out is `unfinished`; a scope that was reconciled or declined by the lane (the source does not own the folder) is settled and never repeated. The unfinished scopes of a pass are run again as they were planned (no re-ranking or re-admission) 1 minute after it ended, and what is still unfinished 5 minutes after that pass, then left to the broad scan: three passes at most per boot, each under the same budgets, none while the app is shutting down, and the pending timer is dropped by `cancel()`. A pass that threw before it finished (for instance, no router lane yet) is repeated from the same input. A repeat occupies the lane like the first pass, so a live watcher scope that flushes meanwhile waits at most the pass's 20 s. One INFO line per pass, `Hot-directory catch-up finished`, carries counts only (`unfinished` is a number, `retry` says whether it was a repeat). Windows and Linux watch roots are the named folders themselves, so only subfolders found through the recent files are covered.

The FSEvents history of the downtime gap is deliberately not replayed. The `fsevents` `since` argument is unvalidated: NaN, a fraction or a small number replays the whole retained log (about two months on the development machine), and an id above the current one yields only `HistoryDone` while later live events carry lower ids. The module exposes no volume UUID, current id or retention bound, so a persisted watermark cannot be checked and truncated history cannot be detected; a replay-derived root `event-loss` would also queue ahead of the hot pass. Take it up only as its own change with a validated watermark and hot-lane-first ordering. The behaviour is covered by injected-dependency tests (`indexed-source-event-router.hot-lane.test.ts`, `file-provider-hot-catchup-service.test.ts`, `file-provider-boot-pass-service.hot-catchup.test.ts`, `file-provider-watch-subtree-reconcile-service.test.ts`, `file-provider-subtree-persist-service.test.ts`, `file-watch-subtree-service.test.ts`); a real Electron boot after a downtime gap has not been run, so how much of the 8 s a large folder still spends on the gate and lease for the files that did change is unmeasured on a real boot.

## 5. Lifecycle is awaited

Watcher shutdown stops intake before closing native streams, awaits registration and metadata work, and suppresses late callbacks. The module closes its streams on `BEFORE_QUIT_STOP_WATCHERS` as well as in `onDestroy` through one shared promise, so the quit flow can stop them before module unload without closing twice. Router unsubscribe detaches producers, drains file/app queues and pending subtree reconciliations, then disposes the queues. Reconciliation uses the runtime's mutation lease and streaming sinks; it must not publish side effects through a second uncoordinated writer.

## Verification limits

The contract is verified by injected-backend lifecycle, overflow, alias, symlink, depth, cancellation, queue, and scoped-delete tests plus a live macOS native event test and the production watcher benchmark. A live symlink-heavy home tree, native kernel-overflow reproduction, and candidate packaged Electron idle-energy comparison remain host-acceptance gaps; they must be reported as partial evidence rather than silently promoted to product-wide guarantees.
