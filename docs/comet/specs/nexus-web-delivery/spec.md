# nexus-web-delivery

Nexus 的地理位置展示、双语文档和按需资源交付。文档以预渲染 HTML 提供可读正文，站内导航读取静态正文数据，交互组件在实际使用时加载。

## Requirement: 地图复用现有组件

Dashboard 概览和设备页使用现有 TuffEx `TxBubbleMap` 展示位置。底图读取本站世界 GeoJSON，不加载 Leaflet、unpkg 脚本或 OpenStreetMap 瓦片。

点位保留调用方的记录身份、经纬度、标签、数值和颜色。经纬度必须为有限数，缺失坐标不生成点位。点选事件返回对应记录，位置更新后同步显示。标签按文本渲染，不把外部位置名称作为 HTML 执行。

使用 SVG 世界地图的缩放和平移能力，不模拟街道瓦片。无有效点位时显示与当前页面语言一致的空态。组件随页面尺寸变化，卸载后释放自己的观察和事件资源；概览和设备页继续懒加载地图。

验证示例：同一记录的位置、名称和数值在两页保持一致；点击地图点位能取得该记录。移除全部有效坐标后出现空态，地图网络请求中没有 Leaflet 或外部瓦片。

## Requirement: 文档目录与静态文件使用同一身份

文档页面、目录 index 和目录别名通过现有路径规范化规则指向同一文档。中英文的文档根、Developer、Concepts 和组件目录具有对应静态 HTML、JSON 及原始 Markdown；JSON 的目录拼写和 index 拼写都可读取。

侧栏、章节链接、组件标签和正文内链保留读者所在文档路由的语言。源文件相对链接仍相对渲染文档解析，不直接交给浏览器猜测当前 URL。既有无语言前缀的文档入口保留正式重定向约定。

完整加载、站内导航及前进后退展示相同正文。有效目录不会因请求不存在的静态 JSON 而误报未找到。不存在的文档展示真实未找到结果，不返回首页作为成功文档，也不循环请求查询参数回退。

验证示例：从 Button 页点击 Developer 和 Concepts，再前进后退，正文与直接访问对应目录相同。生产产物内同时存在目录及 index 的 JSON 别名。

## Requirement: 文档显式语言与周边 UI 一致

`/zh/docs/...` 和 `/en/docs/...` 中的语言是当前文档的语言来源。正文、侧栏、页内目录、导航、周边 UI 和本页 Demo 使用同一语言，SSR、hydration 与站内切换保持一致。

语言切换保留当前文档身份及可保留的页内位置。消息按现有路由分块加载，不展示未翻译的键名，不通过删去中文字符冒充英文翻译。快速切换时只允许最后一次路由选择决定最终语言和内容，旧消息或旧正文响应不切回前一种语言。

文档路由不会被浏览器、cookie 或迟到的账户语言同步改写。直接访问带语言的文档不主动改写账户偏好；显式语言按钮继续使用既有用户偏好约定。文档之外的语言优先级不在本能力中调整。

验证示例：浏览器偏好中文时直接打开英文 Button，正文与周边 UI 都为英文；切回中文后刷新仍为中文。中文与英文快速往返后，URL、正文和导航以最后一条路由为准。

## Requirement: 动态导入的样式保持动态

TuffEx 静态组件导入获得该组件及其样式依赖。动态组件导入不会在声明导入的模块中生成提前执行的静态 CSS 导入；组件激活时才加载其组件样式和实际依赖。

样式依赖仍由已有构建依赖表决定，包含组件依赖的完整闭包。共享依赖只加载一次，已经显式导入的样式不重复下载。类型导入不触发组件样式。既有基础变量和公共样式保持可用，不能用全量组件样式表补偿按需导入错误。

验证示例：只有 Button 动态入口的模块在未激活前不请求 Button 样式，激活后按钮显示完整样式。带依赖的组件激活后，其依赖样式也生效；另一页面使用同一依赖时不重复下载。

## Requirement: TuffEx 有状态模块保持单一实例

Nexus 同一运行模式下的自动注册组件、显式子路径组件和工具模块采用同一套 source/dist 解析。开发允许既有可选模式，生产也必须使用一致来源，不能一部分组件来自 source，另一部分工具来自 dist。

Toast 组件读取发出 Toast 的队列。Overlay 共用同一个层级分配器。统一来源不修改公共组件 API、不增加兼容别名、不通过复制队列或桥接两份模块状态掩盖问题。

验证示例：生产预览的 Toast Demo 点击后出现真实提示。多个 Overlay 的显示及关闭遵循同一层级管理，不出现提示丢失或层级状态分裂。

## Requirement: 站内切页读取完整正文响应

未缓存的文档站内导航直接请求包含元数据与正文的完整响应。正文不依赖先取得 meta、再经过 timer 或 idle 等待请求 body。静态 JSON 优先，开发环境继续使用既有必要回退，不另建一套 API。

文档身份与语言共同决定缓存及在途请求身份。目录和 index 规范化后共享缓存，不同语言不串用缓存。同一请求合并到现有在途请求；再次访问已缓存文档复用已有数据。

新的导航拥有新的请求代次。离开页面后，迟到响应、等待后恢复的旧请求及旧语言结果不能覆盖当前页面。加载状态在成功、未找到或失败时结束；失败保留明确错误和已有重试入口，不把网络失败描述成有效文档不存在，也不增加无界重试。

验证示例：清空页面缓存后从 Button 导航到另一组件，正文通过一个完整数据响应显示，没有先后两次 meta/body 等待。两次快速跳转或切语言后，先发后到的响应不改变最后页面；返回已缓存文档不重新请求完整正文。

## Requirement: 页面只携带实际使用的组件和 Demo

公共页面壳使用公共依赖。文档组件和 Demo 按本页内容解析出的使用集合加载，并保留这些组件的实际依赖闭包。其他文档的交互 Demo、重型库和样式不因一份全局注册表进入本页首屏依赖。

Demo 继续采用现有激活和可见性规则，在实际激活时加载实现。Demo 的文字介绍与代码块可独立静态阅读，交互、重置、语言、键盘操作及减少动态效果约定保持有效。不得删除 Demo、隐藏已展示功能或用成功 mock 代替真实组件。

验证示例：Button 首屏没有未使用的 Calendar、图表或其他页面 Demo 资源。滚动激活本页 Demo 后正常交互与重置；转到其他组件页时只增加目标页所需依赖。

## Requirement: 预渲染正文独立可读且可正确接管

SSR 和预渲染请求完整正文。中英文文档的标题、正文、代码及必要 SEO 信息直接存在于 HTML，JavaScript 禁用时仍可阅读。

hydration 的正文模式、数据身份与服务器一致，已渲染正文保留，不退回空壳或骨架，不为同一首屏重新请求正文。交互功能按需加载不影响正文是否存在。

保留 `<route>.html`、目录 HTML 别名、canonical、alternate、真实 404、静态入口重定向和既有静态缓存窗口。公共静态缓存不扩大到评论、反馈、参与记录、助手或账户数据。旧部署的缺失资源不能被当作本地新产物已验证的行为。

验证示例：生产预览禁用 JavaScript 后打开中英文 Button 和目录页已有正文。启用 JavaScript 后正文不消失，首屏网络观察中没有重复正文请求。文档链接及 SEO 信息保持正式域名和对应语言。

## Requirement: 优化结果有同条件运行证据

验收包含生产构建或等价生产预览的真实浏览器观察。地图、目录导航、中英切换、普通组件页、按需 Demo 和 Toast 都有实际操作证据；源码断言、开发模式截图或编译成功不能替代它们。

前后资源比较采用相同构建模式和缓存条件，记录请求数、CSS/JS 资源、关键串行等待及页面可读状态。直接访问、hydration 和站内导航分别报告。只报告实际测得的变化，不将历史部署、开发模块数或本机网络耗时外推为线上收益。

本能力不自动执行部署、修改 Cloudflare 规则、提交、合并、推送或创建 PR。依赖部署才能生效或观察的边界明确列出，独立工作区和证据在授权收尾前保留。
