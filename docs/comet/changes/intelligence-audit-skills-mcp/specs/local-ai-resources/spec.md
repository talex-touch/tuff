# 本机 AI 资源（技能页与 MCP 页）

## 目标与适用范围

「设置 › 智能」下的「技能」与「MCP」两页，是同一套「本机 AI 资源」清单。两页的用途：

- 看本机各代理（Claude、Codex、Gemini、Cursor、OpenCode、Pi / omp 等 CLI）配置了哪些技能与 MCP 服务器；
- 决定其中哪些在 Tuff 中启用；
- 管理 Tuff 自己的内置技能与手动 MCP 服务器。

Tuff 只复用本机 CLI 的凭证并调用它们，不是 cc-switch 式管理器。本机发现一律只读，开关只影响 Tuff 自己。

## 两页共用

版式自上而下：

- 标题行：复用共享洞察组件，右侧放「重新扫描」「添加」；
- 代理统计条：显示「Tuff 已启用 n / 总数」，再给每个本机代理一个数量胶囊；点胶囊按该代理筛选，再点一次取消；
- 搜索；
- 全宽清单；
- 右侧详情抽屉。

代理显示规则：

- 只显示本机检测到、且至少有一项资源的代理，按数量降序排列。
- 品牌图标用 simple-icons：Claude、OpenAI / Codex、Gemini、Cursor、OpenCode、Pi / omp；其余代理用字母徽标。图标类名进入 UnoCSS safelist。
- 清单行里的代理图标只读：已配置的点亮，未配置的变淡；悬停说明「该代理已配置」。

状态：

- 首次加载显示骨架，骨架与真实版式一致；
- 扫描失败显示带重试的错误提示条；
- 没有本机资源、搜索无结果，各有空态。

控件只用 TuffEx 与共享组件，中英文案同步。

### Scenario: 代理统计与按代理筛选

验收：A24

WHEN 本机装了 Claude、Codex、Pi，打开技能页。
THEN 统计条只显示这三家，数量与各代理目录里的技能数一致。
AND 点「Codex」后清单只剩 Codex 有的技能；再点一次，恢复全部。

### Scenario: 两页的真机外观

验收：A29

WHEN 在隔离 dev 实例中分别打开技能页与 MCP 页，并构造有数据、加载中、扫描失败、无资源四种情形。
THEN 四种情形分别显示清单、与真实版式一致的骨架、带重试的错误提示、空态；暗色与亮色各有截图。
AND 标题行与语音页、审计页一致。

## 技能页

路由 `/setting/intelligence/capabilities` 保持不变。页面与侧栏里的「能力」全部改称「技能 / Skills」，与提示词页共用的文案不受影响。

清单分两组：

- **通用技能**：本机技能，一份真实文件占一行。
  - 主进程按真实路径（realpath）合并：一份文件带出全部来源代理及其条目路径，以及包含它的根目录；不再只保留第一个命中的代理。
  - 存放位置标签取以下之一：cc-switch 库、`~/.agents` 共享层、本地、Tuff 导入、其他位置。
  - 行内容：名称、存放位置、一行描述、代理图标、「在 Tuff 中启用」开关。开关立即生效。
- **内置技能**：原有的 31 项，组内顺序不变。行内容为名称、当前渠道 · 模型、「配置 ›」。

抽屉：

- 内置技能抽屉：
  - 可配置渠道、模型、提示词，并可测试；
  - 改动先进抽屉内的草稿，点「保存」才写入；
  - 有未保存改动时关闭抽屉，先询问保存 / 放弃 / 取消；
  - 有未保存改动时「测试」不可用，并提示先保存。
- 本机技能抽屉：名称、描述、来源代理列表（代理名 + 该代理目录里的条目路径）、真实位置与存放位置、「在 Tuff 中启用」开关。

「添加目录」管理用户链接的技能目录，从智能页搬来。智能页不再有「技能」「本地技能目录」两组。

### Scenario: 同一份文件只占一行

THEN 共享的技能只占一行，行内 Claude、Pi 图标点亮，存放位置显示它的物理根。
AND 同名的另一个文件单独成行。

### Scenario: 内置技能抽屉先存草稿

验收：A26

WHEN 在「对话」内置技能抽屉里改了模型，不保存就关闭。
THEN 先询问保存 / 放弃 / 取消；有未保存改动期间「测试」不可用。
AND 保存后配置写入，「测试」恢复可用。

### Scenario: 改称技能并搬入目录管理

验收：A31

WHEN 查看侧栏、技能页与智能页。
THEN 「能力」在页面文案与侧栏里都显示为「技能 / Skills」，提示词页文案不变。
AND 智能页没有「技能」「本地技能目录」两组；技能页的「添加目录」可以添加、移除用户链接的技能目录。

## MCP 页

路由 `/setting/intelligence/mcp` 保持不变。

清单：

- 一行一个服务器。名称相同、传输身份也相同的服务器合并成一行，列出配置了它的代理。传输身份：stdio 为命令加规范化后的参数，HTTP 为地址。
- 行内容：名称、传输方式（stdio / HTTP）、命令或地址摘要、含敏感值标记、代理图标、「在 Tuff 中启用」开关。
- 手动添加的服务器同样占一行。
- 主进程的服务器清单接口是 host-only，不返回任何秘密值。

每个服务器单独启用：

- 已接入的服务器：开关只翻转这一台的启用状态，运行时立即按新状态生效。
- 未接入的服务器：开启时只接入这一台，只迁移这一台的配置与秘密。
  - 秘密按服务器确认：只有安全存储里还没有相同值的秘密才需要确认。
  - 已经接入过同一配置文件里其他服务器时，新选中的服务器与已有服务器合并：保留已关闭的状态，不删除已有的秘密。
  - 选择中排除了需要 OAuth 或重新授权的服务器时，其余服务器照常接入。
- Claude 等来源配置文件位于代理目录之外的情形（如 `~/.claude.json`），同样能接入。
- 关闭只停这一台，同一配置文件里的其他服务器不受影响。
- 开启失败时，显示具体原因（需要确认敏感值、需要重新授权、配置在预览后被改），不显示通用失败文案。

抽屉：

- 内容：来源代理与配置文件路径；命令与参数；环境变量名（值掩码）；探测结果与「探测」按钮。
- 探测只启动这一台服务器。
- 手动添加的服务器可编辑；删除前先确认。

清单下方保留「本机 MCP 服务 · 让其他 AI 调用 Tuff」卡片：功能不变，按新版式换皮。以下安全行为保持不变：令牌掩码；读取失败不显示成「未开启」；含敏感值先确认。

### Scenario: 同一服务器合并且逐台启停

验收：A27

WHEN Claude 与 Codex 都配置了 context7（同一命令），并且只开启 context7。
THEN 清单里 context7 只有一行，Claude、Codex 图标点亮；同一配置文件里的其他服务器保持未启用。
AND 之后关闭 context7，pencil 的启用状态不变。

### Scenario: 敏感值确认、掩码与失败原因

验收：A28

WHEN 开启一台含敏感环境变量的服务器，并打开它的抽屉。
THEN 开启前要求确认，抽屉里环境变量的值显示为掩码。
AND 开启因需要确认敏感值、需要重新授权或配置在预览后被改而失败时，提示写明对应原因。

### Scenario: 本机 MCP 服务卡片保持安全行为

验收：A32

WHEN 查看 MCP 页清单下方的「本机 MCP 服务」卡片，并模拟读取失败。
THEN 卡片功能与原页面一致，令牌掩码；读取失败显示错误，不显示成「未开启」；含敏感值的操作先确认。
AND `SettingMcpHost` 等原有测试迁移后通过。

### Scenario: 手动服务器与逐台探测

验收：A33

WHEN 手动添加一台服务器，并对任一服务器打开抽屉。
THEN 手动服务器在清单里占一行，可以编辑，也可以确认后删除。
AND 抽屉展示来源代理与配置文件路径、命令与参数、环境变量名；「探测」只启动这一台，并显示结果。

## 只读边界

两页的扫描、合并、筛选、启停与探测，都不写入任何代理目录或 CLI 配置文件，不创建链接，也不替 CLI 切换 provider。Tuff 的状态只写在 Tuff 自己的存储里。参考图中的安装、恢复、导入到代理、同步、检查更新等管理功能不提供。

### Scenario: 发现与开关不写代理目录

验收：A30

WHEN 在测试夹具中扫描本机资源，并对技能、MCP 服务器执行启用与停用。
THEN 各代理目录与 CLI 配置文件的文件树快照前后一致。
AND 变化只出现在 Tuff 自己的存储里。
