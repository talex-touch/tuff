# 目标

把 Home 输入框（`/home` 的 composer）重新做得清爽：工具条只留必要信息；权限、对话/智能体、模型三个弹层按 PI-Desktop 的克制程度简化，并修掉模型弹层整块滚动、搜索框被裁掉半截的问题。同时让语音听写用上 TuffEx 里已有的 `TxVoiceBeam`（libraries.dev Voice 的 Vue 移植，2026-09-28 已并入 TuffEx）：听写时输入框底部出现随声音起伏的辉光，工具条上的其他控件隐藏。

# 范围

## 工具条（静止态）

- 布局不变：左侧依次是「+」、权限胶囊、模式胶囊（Main 忙且有草稿时多一个排队键）；右侧是模型胶囊、麦克风、发送。
- 去掉权限、模式胶囊的彩色底和描边（现在是红底「权限 · 完全允许」、蓝底「Agent · Tuff Pi Coordinator」），也去掉「权限 ·」「Agent ·」前缀。
- 胶囊始终显示「图标 + 文字」，平时透明，悬停才出底色（Q1：A 文字胶囊）。「完全允许」的图标和文字用警示色。
- 胶囊换档不再做变形动画：图标和文字在同一帧换成新值，没有模糊、宽度补间和底色过渡，只保留按下反馈；弹层展开沿用全局 expand（Q2：A）。
- 保留现有窄宽度行为：工具条窄于 520px 时文字胶囊折叠成图标，完整状态留在可访问名称里。

## 权限弹层

- 三行：禁用 / 自动审阅 / 完全允许。每行只有图标、名称和当前项的勾，去掉每行的说明文字；说明改为悬停提示。
- 「自动审阅」时保留末尾的「重置已记住的授权」。
- 选「完全允许」要在行内再点一次（Q3：A）：第一次点击时该行变红，显示「再点一次确认：之后所有工具调用都不再询问」；第二次点击才生效。不切换整块面板。关闭弹层或改选其他档位，待确认状态即取消。

## 模式弹层（对话 / 智能体）

- 现在的弹层把三件事放在一起：选模式、选 profile、启停 profile（每行同时有 ✓ 和开关）。调查确认：这个弹层是目前唯一能启停 orchestrator profile 的界面（设置里的 Agents 页管的是 `AgentDescriptor`，不是 `AiAgentProfile`），所以启停能力不能直接删。
- 平铺列表 + 「管理智能体」二级页（Q4：A）：第一层只有「对话」和已启用的 profile，没有说明文字和开关，选 profile 即切到 Agent 并使用它；「管理智能体」进入二级视图，列出全部 profile 的摘要和启停开关；已有历史的会话在底部显示一行「切换后在新分支里继续」。
- 保留现有行为：只能选真实且已启用的 profile；已有历史的会话切模式会在新分支继续；回复进行中不能切；没有 profile、全部关闭、读取失败时有明确文字和入口。

## 模型弹层

- 输入框和顶栏的模型胶囊共用这个弹层（调查确认：`HomeTopBar` 也挂着同一个 `HomeModelMenu`），改版两处同时生效；输入框向上、顶栏向下展开。
- 双栏（Q5：A 单层结构；Q8：C 双栏）：顶部是搜索框和设置键，中部左栏是「自动选择 / 最近使用 / 各来源」、右栏是所选来源的模型，底部是推理强度。只有中部双栏滚动，打开时搜索框完整可见并获得焦点。
- 左栏：有渠道的服务（OMP 本机 CLI 的 ccs、codex 等）显示组头，并缩进列出渠道和模型数；没有渠道的服务直接是一项。打开时停在当前模型所在的来源。
- 「最近使用」自动记录最近选中的 5 个模型，替代收藏；每行行尾标来源。
- 搜索跨所有来源，结果按来源分组；搜索时左栏变淡。
- 去掉：provider 筛选条、每行副标题、字母占位图标、收藏 ★、⌘1–9（Q6：A）；已存的收藏数据保留，不删。

## 听写态

- 点麦克风后：输入框底部出现 `TxVoiceBeam` 辉光，随听写电平起伏；附件、权限、模式、排队键、模型控件隐藏，且不可点击、不可聚焦。
- 左侧显示状态：「正在准备麦克风...」→ 录音点 +「正在听写」+ 计时 +「Esc 取消」→「正在识别」。麦克风变为停止键（结束听写，文字留在输入框），发送键为「结束听写并发送」，Esc 取消并还原听写前的草稿。这些行为沿用现有 `useComposerDictation`，只改呈现。
- 停止后等待最后结果（「正在识别」）时，辉光收拢成一束往返扫动的光并保持点亮（`TxVoiceBeam` 的 `processing`），识别结束后淡出。
- 结束、取消或失败后，辉光淡出，工具条恢复。
- 辉光用 Tuff 品牌色，与回复时输入框的流光是同一组颜色（Q7：A）。

## 复用 TxVoiceBeam

- 2026-10-05 Build 开始时查明：`TxVoiceBeam` 已在 TuffEx 中（提交 `6ac652963`，2026-09-28，`packages/tuffex/packages/components/src/voice-beam/`，since 0.6.2），Nexus 中英文文档在 Effects 分类，core-app 还没有使用它。它移植自上游较早的版本：那时「处理中」扫光（`processing`）仍是 MIT 免费功能，所以现有组件带扫光，没有 0.3.0 才加入的 `motion` 和未发布的 dots / lines 表面。
- 本 change 直接使用现有组件：`level` 取值函数驱动、`active` 淡入淡出、`processing` 用于「正在识别」、`theme` 跟随应用主题、`colors` 传入 Tuff 品牌色。不修改组件及其文档，也不升级到上游 0.3.0（升级会失去 MIT 版本的扫光，换来的 `motion` 和 dots / lines 用不上）。现有组件在减少动态效果时扫光偏移固定为 0，光束停在中间（`voice-driver.ts` 第 683 行）。

# 非目标

- 不改权限、模式、模型、推理强度的语义和持久化（`appSetting.tools`、会话设置、orchestrator profile 的保存），也不改 Main。
- 不改 CoreBox 搜索框；只改 Home 的 composer，以及与它共用模型弹层的 Home 顶栏模型胶囊。
- 不新建设置页；profile 的启停仍留在 composer 里，放在模式弹层的「管理智能体」二级页。
- 不修改 `TxVoiceBeam` 组件及其文档，不升级到上游 voice-glow 0.3.0；不实现付费版的 Recording pill 宿主和未发布的 dots / lines 表面。
- 不改全局锚点弹层的 expand 动画。
- 不提交、不合并、不推送、不建 PR；这些要另行授权。

# 约束与不变量

- 遵守前端规范：新的通用视觉行为放 TuffEx，CoreApp 只做薄封装；TuffEx 组件改动与 Nexus 中英文文档、demo 同一提交交付；颜色只用 token；悬停不做颜色过渡；交互元素用语义控件；等待数据的界面默认用与真实排布一致的骨架。
- 保留现有可访问性：可访问名称包含可见文字（label-in-name）、键盘可达、焦点回到触发胶囊、`prefers-reduced-motion`、`html.contrast`、深浅色。
- 新增或删除的界面文字走 CoreApp 中英文消息目录，中英文键一一对应，且都能被 vue-i18n 编译（`coreapp-i18n-messages` 规格）。
- 不破坏 `agent-desktop-workspace` 规格里与 composer 相关的行为：只能选真实且已启用的 profile、改模式在新分支继续、没有可用 profile 时明确引导。
- 大于 100 MB 的产物放 `/tmp`；真实应用验证用隔离 profile，不碰老板正在用的实例和数据。

# 决策

- Q1（用户 2026-10-05 选 A）：工具条用文字胶囊，始终显示图标 + 文字，平时透明。
- Q2–Q7（用户 2026-10-05 选「方向一」，即 Pen 设计稿里的那一组）：Q2 A、Q3 A、Q4 A、Q5 A、Q6 A、Q7 A。
- Q8（用户 2026-10-05 选 C）：模型弹层改为双栏，左栏选来源、右栏选模型。
- D1：用户要求把 Voice 融入 TuffEx；Build 开始时查明它已在 TuffEx（`TxVoiceBeam`，2026-09-28），因此不再新移植，直接使用。
- D2：Tuff 的录音在主进程，渲染层拿到的是 `asrStream` 约 10 Hz 的电平帧，没有 MediaStream。所以组件用 `level` getter 驱动，由帧驱动自带的 attack / release 做平滑。
- D3：「正在识别」阶段打开现有组件的 `processing`：辉光收拢成一束往返扫动的光并保持点亮，识别结束随辉光一起淡出。（Shape 初稿以为上游 0.3.0 才是唯一来源而写成「回落为静止呼吸」，查明现有移植带 MIT 版本的扫光后改正。）
- D4：辉光作为 composer 内部的覆盖层挂载，而不是包住 composer。原因：上游包裹层带 `overflow: hidden`，包住 composer 会裁掉它的阴影和焦点环。
- D5：听写期间关闭空输入框的 `TxBorderBeam` 呼吸光，避免两种特效叠在同一个元素上。
- D6：`agent-desktop-workspace` 规格不改，composer 的呈现写进新的 `home-composer` 规格。
- D7：双栏弹层约 480px 宽，超过 `TxDropdownMenu` 写死的 360px 上限，改用 `TxPopover`（可设 maxWidth）承载；权限、模式弹层仍用 `TxDropdownMenu`。
- D8：打开模型弹层时，左栏停在当前模型所在的来源；当前为自动选择时，「最近使用」非空则停在它，否则停在第一个来源。左栏的「自动选择」是动作：点了即改为自动，并关闭弹层。
- D9：「最近使用」指在模型弹层（输入框或顶栏）里最近选中的模型，最多 5 个，去重，最新的在前，存进 `appSetting.conversation`，重启后保留；自动选择不计入；不可用的模型不显示。
- D10：搜索按模型 ID、显示名、服务名、渠道名匹配，结果按来源分组；搜索时左栏变淡且不可操作，清空后恢复原选择。键盘：在搜索框按 ↓ 进入右栏，←/→ 在两栏间切换，Enter 选中，Esc 关闭并回焦。
- D11：设置键关闭弹层，并打开 `/setting/intelligence/channels`。
- D12：删除模型弹层的 ⌘1–9 快捷键实现和收藏星标界面（`model-menu-hotkeys.ts`、`useModelFavorites` 不再有调用方）；`appSetting.conversation.favoriteModels` 里已存的数据不删。
