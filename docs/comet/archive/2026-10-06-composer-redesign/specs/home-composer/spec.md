# Home 输入框（Home Composer）

## Purpose

本规格描述 Home 页输入框（`/home` 与 `/home/c/:id` 的 composer）的呈现与交互：工具条、权限弹层、对话/智能体弹层、模型弹层和语音听写态。权限档位、会话模式、Agent profile、模型与推理强度的语义和持久化由各自的现有权威负责（`appSetting.tools`、会话设置、orchestrator profile、`agent-desktop-workspace` 规格），本规格不改变它们，只规定用户在输入框上看到和操作的内容。

## Requirement: 工具条与胶囊

工具条左侧依次是附件键、权限胶囊、模式胶囊；Main 忙且草稿不为空时，模式胶囊之后多一个「加入队列」键。右侧依次是模型胶囊、麦克风键、发送键；当前构建无法录音时不显示麦克风键。

权限、模式、模型三个胶囊同属一种样式：始终显示图标和文字，平时没有底色、描边和彩色色调，悬停或弹层打开时才出现中性底色；悬停的底色变化是即时的，不做颜色过渡。权限胶囊只显示档位名（禁用 / 自动审阅 / 完全允许），模式胶囊只显示「对话」或所选 profile 的名称，都不带「权限 ·」「Agent ·」之类前缀。「完全允许」时权限胶囊的图标和文字使用警示色，其余档位使用常规文字色。模式胶囊在对话模式用对话图标，在 Agent 模式用机器人图标；会话所用的 profile 已关闭或不存在时，模式胶囊的图标和文字使用警示色。模型胶囊依次显示模型图标、模型名、推理强度（选了具体档位时以「· 档位」显示）和展开箭头，弹层打开时箭头朝上。

工具条宽度小于 520px 时，权限和模式胶囊折叠为只有图标的圆键；每个胶囊的可访问名称始终包含它的完整状态（例如「权限 · 完全允许」），并包含界面上可见的文字。

### Scenario: 静止态的工具条

验收：A1

WHEN 打开 Home，权限为「完全允许」、会话为 Agent 模式且使用「Tuff Pi Coordinator」。
THEN 工具条左侧显示附件键、警示色的「完全允许」胶囊和「Tuff Pi Coordinator」胶囊，右侧显示模型胶囊、麦克风和发送键；三个胶囊都没有底色、描边和前缀，悬停时出现中性底色。把窗口缩到工具条窄于 520px，权限和模式胶囊变成图标圆键，读屏仍能读出完整状态。

## Requirement: 换档不做变形动画

权限档位、模式或模型改变后，对应胶囊在同一帧显示新的图标和文字；不做图标模糊替换、文字模糊淡入、宽度补间或底色与文字颜色的过渡。按下胶囊时的缩放反馈保留。三个弹层的展开与收起沿用全局锚点弹层的 expand 动画，不在输入框内另设动画。系统开启减少动态效果时，胶囊和弹层都不做位移与缩放动画。

### Scenario: 切换权限档位

验收：A2

WHEN 在权限弹层把「自动审阅」改成「禁用」。
THEN 弹层关闭的同时，胶囊直接显示「禁用」和对应图标，宽度直接变为新值，期间没有模糊、宽度补间和颜色过渡。

## Requirement: 权限弹层

权限弹层只有三行：禁用、自动审阅、完全允许。每行只显示图标和档位名，当前档位行尾有勾；「完全允许」行的图标使用警示色。原来每行下方的说明文字不再显示，改为该行的悬停提示。当前档位为「自动审阅」时，三行下方以分隔线隔开显示「重置已记住的授权」，选中后清除已记住的授权并关闭弹层；其他档位不显示这一行。

从其他档位改为「完全允许」需要在行内确认两次：第一次选中「完全允许」时档位不变，弹层不关闭，这一行变为警示底色并在档位名下显示「再点一次确认：之后所有工具调用都不再询问」，读屏会播报这句提示；第二次选中这一行才切换到「完全允许」并关闭弹层。行处于待确认状态时，选中其他档位、关闭弹层或重新打开弹层都会取消待确认状态。选中其他档位立即生效并关闭弹层。

用键盘或选择关闭弹层时，焦点回到权限胶囊；点击弹层外部关闭时焦点留在用户点击的位置。

### Scenario: 开启完全允许

验收：A3

WHEN 当前为「自动审阅」，打开权限弹层。
THEN 弹层只有三行档位和「重置已记住的授权」，没有每行说明；「自动审阅」行尾有勾。第一次点「完全允许」，档位不变，该行变红并显示「再点一次确认：之后所有工具调用都不再询问」；再点一次，档位变为「完全允许」，弹层关闭，胶囊变为警示色。若第一次点击后按 Esc 关闭再重新打开，该行恢复为普通状态。

## Requirement: 对话与智能体弹层

模式弹层的第一层只列出「对话」和全部已启用的 Agent profile，每行只有图标和名称，当前项行尾有勾，不显示说明文字、profile 摘要或启停开关。选中某个 profile 即切换到 Agent 模式并使用该 profile；选中「对话」即切换到对话模式。会话已有历史时，弹层底部显示一行「切换后在新分支里继续」；Main 正在处理当前回复时，需要分支的切换不可用，该行提示改为「回复结束后才能切换」。

第一层底部的「管理智能体」进入第二层：顶部是返回第一层的「管理智能体」标题行，下面列出全部 profile，每行显示名称、摘要（运行时 · 工具数 · 审批方式）和启停开关，开关通过 orchestrator 现有的保存入口启用或关闭 profile。关闭当前会话正在使用的 profile 后，模式胶囊按「会话所用 profile 不可用」显示警示色。重新打开弹层时总是回到第一层。

每次打开弹层都会重新读取 profile。首次读取期间，profile 行的位置显示骨架；读取失败时显示「无法读取 Agent profile」和重试入口；一个 profile 都没有时说明 Agent 模式没有可运行的配置；全部关闭时提示在「管理智能体」里开启一个；会话所用的 profile 不可用时提示另选一个。

### Scenario: 选择与管理智能体

验收：A4

WHEN 在一个已有历史的对话会话里打开模式弹层。
THEN 第一层只有「对话」和已启用的「Tuff Pi Coordinator」，底部显示「管理智能体」和「切换后在新分支里继续」。选中「Tuff Pi Coordinator」后在新分支里以 Agent 模式继续，胶囊显示该 profile 名称。再次打开弹层并进入「管理智能体」，能看到全部 profile 的摘要和开关；关闭一个 profile 后回到第一层，该 profile 不再出现在列表里。

## Requirement: 模型弹层的结构

输入框的模型胶囊和 Home 顶栏的模型胶囊打开同一个模型弹层：从输入框打开时在胶囊上方右对齐展开，从顶栏打开时在胶囊下方左对齐展开。弹层宽约 480px，窗口不够宽时以窗口为限。

弹层自上而下分三段：顶部是搜索框和设置键；中部是双栏；底部是推理强度。打开时搜索框完整可见并获得焦点。设置键关闭弹层并打开「智能 · 渠道」设置页（`/setting/intelligence/channels`）。只有中部双栏可以滚动，搜索框和推理强度始终可见。

中部左栏依次是「自动选择」「最近使用」和各个来源。有渠道的服务（例如 OMP 本机 CLI 下的 ccs、codex）显示为不可点击的组头（服务图标 + 服务名），其下缩进列出各渠道；没有渠道的服务显示为一项（服务图标 + 服务名）。每个来源项右侧显示该来源的模型数量，当前选中的左栏项有中性底色。右栏列出所选左栏项对应的模型，每行显示模型家族图标（无法识别家族时用服务图标）、显示名（用户设置的别名优先）和当前模型的勾。

弹层不再有服务筛选条、每行的服务 · 渠道副标题、无图标时的字母占位、收藏星标和 ⌘1–9 快捷键；已保存的收藏数据保留不动。

底部推理强度为「自动 · 低 · 中 · 高 · 极高」五档分段控件，显示当前会话的选择。路线不支持推理强度时整排不可用，并在下方用一行文字说明原因；所选档位会被模型降档、走自动选择或由 Tuff 云端处理时，同样用一行文字说明。

### Scenario: 双栏模型弹层

验收：A5

WHEN 当前模型为 OMP 本机 CLI 的 codex 渠道下的 gpt-5.6-luna，打开输入框的模型胶囊。
THEN 弹层在胶囊上方展开，搜索框完整可见并已获得焦点；左栏显示自动选择、最近使用、OMP（本机 CLI）组头及其下的 ccs / codex / kimi 等渠道和数量，以及 Ollama 等没有渠道的服务；右栏是 codex 的模型，gpt-5.6-luna 行尾有勾；底部是推理强度五档。来源和模型较多时只有双栏滚动。弹层里没有筛选条、副标题、星标和 ⌘ 键位提示。

## Requirement: 模型弹层的来源、最近使用与搜索

打开弹层时，左栏选中当前模型所在的来源；当前为自动选择时，「最近使用」不为空则选中它，否则选中第一个来源。选中左栏的「自动选择」即改为自动选择并关闭弹层；当前为自动选择时这一项有勾。

「最近使用」保存最近在模型弹层（输入框或顶栏）里选中的模型，最多 5 个，最新的在最前，同一模型只出现一次，应用重启后仍保留。自动选择不计入。已经不可用的模型不显示在列表里。「最近使用」列表的每行在行尾用小标签注明来源（例如「OMP · codex」或「Ollama」）。

在搜索框输入时，右栏显示所有来源中匹配的模型（按模型 ID、显示名、服务名和渠道名不区分大小写匹配），按来源分组并显示来源组头；左栏变淡且不可操作。清空搜索后恢复搜索前的左栏选择。没有匹配时右栏显示「没有匹配的模型」。

键盘操作：在搜索框按 ↓ 进入右栏；↑ / ↓ 在当前栏内移动；在右栏按 ← 到左栏，在左栏按 → 到右栏；在左栏用方向键移动时右栏随之切换；在模型上按 Enter 选中该模型并关闭弹层；Esc 关闭弹层并把焦点还给打开它的胶囊。

首次读取模型列表期间，左右两栏显示与真实行同样排布的骨架；之后每次打开都会刷新列表，刷新期间保留已显示的行。没有任何可用模型时，右栏说明需要先配置 AI 提供方或安装 pi CLI，并提供打开设置的入口。

### Scenario: 最近使用与跨来源搜索

验收：A6

WHEN 先后在模型弹层里选中 claude-opus-5-5 和 gpt-5.6-luna，然后重启应用并打开模型弹层。
THEN 「最近使用」里 gpt-5.6-luna 在前、claude-opus-5-5 在后，各自带来源标签。在搜索框输入「qwen」，右栏按来源分组列出 OMP 和 Ollama 下的 qwen 模型，左栏变淡；清空搜索后左栏恢复原来的选中项。用键盘从搜索框按 ↓ 进入右栏、按 Enter 选中一个模型，弹层关闭，焦点回到模型胶囊。

## Requirement: 语音听写态

点击麦克风键开始听写后，输入框进入听写态：输入框底部出现 TuffEx `TxVoiceBeam` 辉光，由当前听写会话的电平帧驱动，随声音起伏；辉光使用与回复时输入框流光相同的 Tuff 品牌色，深浅色跟随应用主题。辉光作为输入框内部的覆盖层绘制，不裁掉输入框自身的阴影和焦点外框，输入框里的文字和按键始终显示在辉光之上。

听写态下，附件键、权限胶囊、模式胶囊、加入队列键和模型胶囊隐藏，不能点击，也不能用键盘聚焦。工具条左侧依次显示状态：打开麦克风期间显示「正在准备麦克风...」；听写中显示红色录音点、「正在听写」、m:ss 计时和「Esc 取消」；停止后等待最后结果时显示「正在识别」，此时辉光收拢成一束往返扫动的光并保持点亮（`TxVoiceBeam` 的处理中状态）。麦克风键变为停止键，点击后结束听写、文字留在输入框；发送键表示「结束听写并发送」。按 Esc 取消听写并把草稿恢复为听写开始前的内容。状态变化通过读屏的状态区播报。

听写结束、取消或失败后，辉光淡出，隐藏的控件恢复。听写期间，空输入框时的呼吸光边框不显示，避免两种特效叠在同一个输入框上。系统开启减少动态效果时，辉光不再呼吸、流动或变换色相，但仍对声音大小作出反应；「正在识别」的光束停在中间不往返；控件的隐藏与恢复不做动画。

### Scenario: 听写中只留必要控件

验收：A7

WHEN 在输入框点击麦克风并开始说话。
THEN 输入框底部出现随声音起伏的辉光；附件、权限、模式和模型控件消失且 Tab 无法聚焦到它们；左侧显示录音点、「正在听写」、计时和「Esc 取消」；右侧只剩停止键和发送键。点击停止键后显示「正在识别」，辉光收拢成往返扫动的光束；识别完成后文字留在输入框，辉光淡出，工具条恢复原样。

## Requirement: 真实应用中的完整表现

以上行为在真实的 Electron 应用中成立：浅色与深色主题、高对比度模式、宽窗口与工具条窄于 520px 的窄窗口、纯键盘操作（Tab 进入胶囊、Enter 或 Space 打开弹层、方向键移动、Esc 关闭并把焦点还给胶囊），以及减少动态效果设置下，都能观察到对应的呈现与交互。

### Scenario: 真实应用走查

验收：A8

WHEN 在隔离 profile 的真实 Electron 实例中，分别以浅色、深色、窄窗口、纯键盘和减少动态效果打开 Home，依次操作三个弹层并进入听写态。
THEN 每种条件下工具条、三个弹层和听写态都与本规格一致，没有被裁切的弹层、无法聚焦的控件或残留的旧样式。
