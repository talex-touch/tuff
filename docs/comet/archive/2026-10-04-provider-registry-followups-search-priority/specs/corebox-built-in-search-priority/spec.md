# corebox-built-in-search-priority

## Requirement: 内置入口排序

AppDestinationProvider 的现有可搜索入口在匹配查询时获得正向、有界的默认排序偏置，使没有使用历史的新用户也更容易打开设置等常用 Tuff 页面。

范围包括现有可搜索目录中的设置总览、常用设置子页、主窗口、首页、对话、插件市场、已安装插件、下载和关于等入口。目录现有 searchable/advanced 约束不改变，不新增别名、不扩大召回、不把其他 system provider 或第三方插件一并提权。

排序偏置在现有总分模型内生效，而不是无条件置顶；低相关模糊应用/文件结果不应仅靠类型默认值压住准确命中的内置入口。真正精确的应用/文件意图仍受原有精确匹配保护，置顶、使用频率、最近使用与补全学习继续遵循现有规则。不得重写用户配置或伪造使用次数来达到提权效果。

### Scenario: 默认设置入口无需先训练

- WHEN 无使用历史的用户输入现有设置别名，例如 sz、设置或 settings
- THEN Tuff Settings 被正常召回并得到有界默认加分，排在同查询的低相关模糊结果前
- WHEN 查询命中某个现有常用设置子页或其他 AppDestination 页面
- THEN 同样应用默认偏置，不要求用户先执行多次
- WHEN 查询与内置目录无关
- THEN 不新增内置结果
- WHEN 用户已有置顶、使用历史或明确的精确应用/文件匹配
- THEN 既有优先规则和学习信号继续有效，不被全局置顶或伪造历史覆盖

Acceptance: A9

## Requirement: 实际宿主验证

排序验证覆盖无历史基线、常用别名、无关查询和精确意图竞争，并在隔离 Electron 中观察真实 CoreBox 搜索结果与入口打开行为。主进程分数与渲染结果必须对应，不能只通过测试构造的分数宣称用户看到的排序已经改变。

### Scenario: 隔离 CoreBox 的排序与打开

- WHEN 使用隔离 profile 启动真实 CoreApp 并输入现有设置查询
- THEN 能观察到设置结果的排序和打开正确页面的行为
- AND 验收报告区分已执行场景与未覆盖平台，不使用真实用户配置作为测试写入目标

Acceptance: A11
