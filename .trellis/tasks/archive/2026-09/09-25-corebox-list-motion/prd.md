# CoreBox 列表与 item 加载过渡动效优化

父任务：`09-25-corebox-ux-polish`。调研：`research/motion-audit.md`（带 3 个 /tmp jsdom 探针，已验证）。设计：`design.md`。

## Goal

CoreBox 从打开、输入、结果流入、键盘移动到预览面板开合，整个过程不闪、不跳、不空白。不同类型的 item 出现 / 更新时过渡一致、克制，而且渲染主线程繁忙时仍然顺滑。

## Background

- 默认几乎没有入场动效：`listItemStagger` / `resultTransition` / `coreBoxResize` 默认都是 false（`packages/utils/common/storage/entity/app-settings.ts:459-464`）。"跳"的主因是**布局本身在抖**：
  - 混排列表里每按一次方向键，预览面板就开合一次，结果列在 100% 和 40% 之间翻转，而且面板每次都从透明淡入；
  - 同一查询刷新时，快照先删掉文件行，后到的批次再插回并重排，建索引期间每 ≥500ms 就重复一次；
  - 打开 / 清空时，推荐结果回来之前结果区是空白。
- 门控缺口：CoreBox 窗口里全局低电量开关不生效；网格 FLIP 不受 reduced-motion 影响。
- 预览卡片（计算器、换算等）每按一次键整张重建，彩色描边是主线程每帧重绘。
- 以前踩过的坑不能再走（audit §4）：
  - `mode="out-in"`；
  - 按批次 re-key；
  - 透明 / blur 入场；
  - 宽度过渡；
  - 不封顶的 stagger；
  - 默认开启窗口动画；
  - 结果区"搜索中"占位；
  - 键盘导航平滑滚动；
  - 持续的非合成器动画。
- 与姊妹任务的交界：
  - 方案 D（非键盘改焦点时滚进视口）已由 `09-25-corebox-keyboard-jump` 的 R4 实现；
  - B 与它共用焦点跟随逻辑，**keyboard-jump 通过检查后再做 B**；
  - 渲染层的刷新抖动由 B 处理，"为什么一直在刷新"归 `09-26-corebox-refresh-churn`。

## Decisions（老板 2026-09-26）

- **D1 / D3（默认动效与重排）**：做列表行平滑位移（方案 G）。真机量帧率达标才默认开启，否则挂在「结果切换动画」开关下，默认关闭。stagger 保持默认关闭。
- **D2（预览面板）**：选中文件时立即打开；移到非文件行后延迟约 200ms 再关，期间继续显示上一个文件。
- **D4（同查询刷新）**：等搜索完成再删除本次会话没有再下发的行，并加兜底超时。这改动了 07-15 中间态约定的时序。
- **D5**：不做查询细化时沿用上一次延迟层的行。
- **D6**：空结果维持 07-15 行为。
- **D7（预览卡片描边）**：平时静止，只有被选中时才流动；隐藏、低电量、减少动态效果时停止；改成只在合成器上执行的实现。
- **D8（选中指示）**：新增跟随选中行平移的高亮块，只动 transform；按住方向键不拖尾；受门控，降级为瞬移。

## Requirements

- **R-E 统一门控**：CoreBox 窗口里全局低电量开关生效；所有 JS / WAAPI 动效先判断 `shouldAnimate()`（reduced-motion 与低电量）。
- **R-A 预览面板迟滞**：符合 D2。结果列宽度每次停留最多翻转一次；面板入场只做 translate，不从透明开始；两个文件之间切换不重播入场。
- **R-C 推荐路径不预先清空**：打开 / 清空查询时，由快照一次性替换结果和 layout，中间不出现空结果帧；超时与失败仍然清空。
- **R-B 同查询刷新对账**：符合 D4。刷新期间已存在的行保持原位、DOM 节点复用；complete 时（或兜底超时后）才删除过时行；焦点跟随规则与 keyboard-jump 一致。
- **R-G 列表重排位移**：符合 D1 / D3。已有且移动了的行做 ≤180ms 的 translate，新行不做入场透明；只处理视口附近的行；默认开启与否以帧率测量结果为准。
- **R-D8 跟随高亮块**：符合 D8。列表模式下由一个高亮块承担选中背景；键盘步进时 ≤90ms 追到位，连续按住不拖尾；重排、滚动、resize 时位置正确；hover 不覆盖选中态，键盘操作后到下一次 mousemove 之前不显示 hover。
- **R-F 预览卡片**：符合 D7。同一个 ability 的卡片按键时不重建；描边动画不产生每帧 Paint。
- **R-P2**：
  - 历史面板改为宽度一次到位加 transform 滑入；
  - 高度测量排除容器自身的 translate；
  - 富预览就绪前先显示图标占位。

## Acceptance Criteria

- [ ] AC1（R-A）真机：按住方向键扫过混排列表逐帧截图，结果列宽度每停一次最多翻转 1 次；两个文件之间切换，面板不重播入场。
- [ ] AC2（R-C）真机：用快捷键打开 CoreBox，以及清空查询，逐帧确认旧网格和新网格之间没有空结果帧。
- [ ] AC3（R-B）建索引期间保持一个能命中文件的查询，行数不再忽多忽少，已有行的 DOM 节点保持不变。已改写的 07-15 用例通过。
- [ ] AC4（R-G）延迟层插入时逐帧截图，下方的行是滑下去而不是跳下去。CDP Performance 录制对比有无 G 时的长任务数与丢帧率，据此决定是否默认开启，并记录在本任务 `research/`。
- [ ] AC5（R-D8）按住 ↓ 逐帧截图，每一帧只有一块高亮，不拖尾；鼠标停在列表上同时用键盘移动，hover 不覆盖选中态。
- [ ] AC6（R-F）输入 `123+456` 期间，DevTools Performance 里描边没有每帧的 Paint；同一个 ability 的卡片 DOM 节点不变。
- [ ] AC7（R-E）打开「减少动态效果」或低电量时，上述动效都降级为瞬时到位，内容不被遮挡。
- [ ] AC8 每条方案都有对应单测（老板 2026-09-26 批准补测）；core-app 包内 eslint、`vue-tsc -p tsconfig.web.json`、`views/box` 与相关 hook 的现有测试全部通过；`git diff --check` 干净。

## Out of Scope

- 查询细化时沿用上一次延迟层的行（D5）。
- 结果区加"搜索中"占位；键盘导航平滑滚动；默认开启 `coreBoxResize`。
- 网格模式的高亮块，只做列表模式。
- ActivatedProviders 胶囊动画（audit N），另开任务。
