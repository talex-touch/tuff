# 推荐使用重构实施顺序

1. 锁定已批准 PRD 与跨层接口，激活现有任务；保留工作区其他会话改动。
2. 并行实现有效执行事务与行为读 API、所有执行入口、推荐规则及共享 SDK；集成 owner 实现可见曝光与次数更新。每片只改自己的文件，接口问题即时通知。
3. 接通原始身份、动作 eventId、统计提交订阅与推荐代际；确保失败不变次数、次要动作不变启动次数、非激活成功不漏计。
4. Tester 更新被新产品规则替代的旧契约，补充重复执行/失败回滚、常用跨日门槛、时间置信度与上限、探索预算、缓存失效竞态等必要回归。
5. 全部实现收敛后统一执行相关 Vitest、定向 ESLint、CoreApp node/web 类型检查及 utils 受影响入口检查；不在子任务期间运行检查或 formatter。
6. 构建真实 Electron，使用 /tmp 隔离 profile 与实际数据库样本验证 AC1～AC16 的真实入口/DOM/副作用。真实文件、剪贴板、插件与内置动作分别核对计数；核对无常用空段、两项不凑满、固定文件留列表、热缓存和冷缓存首次快照、退出后保存。
7. 将观察结果记录至任务验收，更新现有统计/推荐契约和 SDK 说明。不提交、不 push、不发布。

回滚边界：不回退或清除用户统计。实现失败保留旧数据，修复当前入口；新增 schema 仅增量兼容，不用删除数据库当恢复措施。
