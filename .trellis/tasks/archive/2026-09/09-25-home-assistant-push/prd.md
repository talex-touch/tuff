# 主页个人助理：默认推送与开场引导

父任务：`09-25-home-session-polish`（R5）

## Goal

Home 的新对话空态不再只是「Logo + 今天想做点什么？+ 输入框 + 4 个写死的快捷胶囊」，而是像个人助理一样默认主动推送：助理先用一两句话结合你本机的情况开口，下面给出可以一键开始的事情，让用户一打开就知道「现在可以让它做什么」。

## 参考（老板 2026-09-25 提供的 miko 截图）

- 助理先开口：一段话概括能做什么，再结合本机上下文点出具体抓手（「你桌面上那些按日期归档的项目、最近在准备的软著材料和面试，哪个想先推一把」）。
- 紧跟一张可翻页的结构化选项卡（`1 / 2`）：标题「我们先从哪件事开始？」，每项是图标 + 标题 + 一行说明。

## 现状（代码事实）

- 空态在 `apps/core-app/src/renderer/src/views/base/home/HomePage.vue:1053-1068`（`.HomePage-Head`：`AppLogo` + `home.greeting`）与 `:1462-1475`（`.HomePage-Pills`）。快捷胶囊写死四项（`:510-515`），点击只是把 `home.pill.<key>` 填进输入框（`applyPill`，`:525-530`）。
- 模型调用：会话走 `useHomeConversation` 的 `sdk.stream('text.chat', …)`（`useHomeConversation.ts`），带 `surface: 'home-conversation'` 元数据时主进程会注入技能 / 规则、pi CLI 还会建本机原生会话；标题生成走 `sdk.text.chat` + `operation: 'conversation-title'`，不带 surface（`conversation-title.ts`）——开场白应当走后一种形态。
- 会话发给模型的只有已完成的消息（`toProviderMessages`），标题生成取「第一条已完成的助手消息」（`HomePage.vue` `maybeGenerateTitle`）。
- 代码库里目前没有任何「主动推送 / 每日简报 / 推荐」类功能，这是新能力。

## 已拍板（2026-09-25）

- **推送形态：两者分阶段**。没有对话历史时走「开场白 + 可翻页引导卡」；有历史之后换成「为你准备」推送列表。
- **内容来源：模型个性化开场**。每次打开新对话，调用模型根据本地摘要写开场白；引导卡与推送卡由本地数据生成。代价（老板已接受）：1–3 秒延迟、每次有 token 成本、必须已配置提供方、本地摘要会发给提供方。
- **布局：居中英雄区 + 开场白**。保留居中的 Logo + 问候语 + 输入框；开场白是问候语下 2–3 行、流式浮现；卡片放在输入框下方，替换快捷胶囊；第一次发送仍是输入框沉到底部。
- **开场白去向：并入对话，成为第一条**。发送第一条消息（或点选卡片）时，开场白成为这段对话里助理的第一条消息，随对话保存；模型后续轮次能看到它说过什么。

## 本地信号（全部来自渲染层现成数据，不新增主进程接口）

| 信号 | 来源 | 发给模型的摘要里 | 用在推送卡 |
| --- | --- | --- | --- |
| 最近对话 | `useConversationHistory().conversations`（`title` / `projectId` / `updatedAt`） | 标题（最多 3 条，7 天内） | 「继续「标题」」 |
| 项目 | `useProjectStore().projects`（`pinned` / `lastOpenedAt`） | 名称（最多 3 个），不含路径 | 「在 某项目 里开始」 |
| 本机 AI 会话 | `useProjectStore().localAiSessions`（`state === 'available'`、`lastSeenAt`） | 数量与所属项目名 | 「继续 某 provider 会话「标题」」 |
| 剪贴板 | `ClipboardEvents.getHistory({ limit: 1, type: 'text' })`（读数据库；**不用** `getLatest({ refresh: true })`，那会在主线程同步读系统剪贴板） | **不发** | 30 分钟内、非密钥（`retentionReason !== 'protected'`）的文本 → 「处理刚复制的内容」，点了只是填进输入框 |
| 当前项目 | `activeProjectId` | 名称 | 推送优先该项目 |

## Requirements

1. **开场白**（模型）
   - 进入空白新对话时发起一次模型调用：`sdk.stream('text.chat', …)`，`metadata.operation = 'home-opening'`（新常量，放在 `packages/utils/types/intelligence.ts`，与 `conversation-title` 同类），不带 home surface、不建原生会话、不带推理强度（避免用「高」档打招呼）；**走和聊天同一条路由**（输入框固定的提供方与模型，没固定就是自动）——2026-09-26 老板拍板，见下一条。
   - 摘要只含上表「发给模型」一列；提示词走语言包（与标题生成同样由调用方从语言包取），要求不超过 3 句、口语化、只提摘要里真实存在的名字、不列清单。
   - 首个 token 前显示两行骨架（镜像开场白布局，不跳动）；2.5 秒内没有首个 token，先换成本地模板开场白**顶着**，调用继续；模型开场白完整写完（30 秒内，从进入空白态算起）就整段替换模板（先淡出再淡入，不在模板上逐字长出来）；30 秒到了还没写完，或没有可用提供方 / 调用失败，模板就是最终结果并取消调用，之后不再替换。
     - 2026-09-26 老板拍板（「走聊天同款路由，放宽等待」）：原先的默认路由在老板环境里落到本机 Claude / Codex CLI，开场白 15–20 秒才出来，2.5 秒一到就被取消，所以永远只见模板。实测：模板 2.8s 出现，CLI 在约 19s 写完并替换。
   - 同一份摘要 10 分钟内再次打开新对话，复用上一次的开场白，不重复调用（控制成本；摘要一变就重新生成）。
   - 用户在开场白生成中就发送：取消生成，这次不并入对话。
2. **引导卡**（无对话历史时）：用 `TxChoiceCard` 渲染两步。
   - 第 1 步「我们先从哪件事开始？」：工作与项目、文件与整理、写作与翻译、资料与分析、自动化（每项图标 + 标题 + 一行说明，对应 Tuff 真实具备的能力，不写做不到的事）。
   - 第 2 步按第 1 步的选择给 3–4 个具体起手任务，有本地数据时带上真实名字（例如项目名）；最后一项是「我自己说」，只聚焦输入框。
   - 选中起手任务：把任务文案放进输入框并走正常发送（与手动发送同一条路径，分裂动画照常）。
3. **为你准备**（有对话历史时）：用 `TxChoiceCard` 单步列表，最多 4 项，按「当前项目相关 → 继续对话 → 本机会话 → 剪贴板 → 最近项目」的优先级取；一项都没有时退回引导卡第 1 步。每项的动作：继续对话 = 打开该对话；本机会话 = 与侧边栏同一个续接入口；剪贴板 = 填进输入框并聚焦（**不自动发送**，用户看到将要发出的内容）；最近项目 = 进入该项目新对话。
4. **并入对话**：发送时若开场白已完整生成，它成为这段对话的第一条助理消息。
   - 发给模型时，「出现在任何用户消息之前的助理消息」统一转成一条系统提示（「对话开始时你对用户说过：…」），兼容要求首条必须是用户消息的提供方与 pi CLI 原生会话；不改会话存储结构。
   - 标题生成改为取「第一条用户消息之后的第一条已完成助理消息」。
5. **布局**：英雄区高度在 600px 可视高度内放得下（Logo → 问候语 → 开场白 → 输入框 → 卡片，卡片两列）；窗口更矮时空态整体可滚动，输入框不被挤出视口。开场白区域预留固定高度，流式输出不引起下方输入框与卡片跳动。
6. **项目空态**：当前是某项目的新对话时，开场白与推送都以该项目为中心。
7. **图标**：卡片图标类名写在 `.ts` 表里，必须按现有做法加入 core-app `uno.config.ts` 的 safelist 并配 `configDeps`，否则图标渲染成空方块（见记忆里 UnoCSS safelist 的教训）。
8. **文案**：全部新文案（提示词、模板开场白、引导卡、推送项、骨架的无障碍文字）进 zh-CN / en-US 语言包，`translation-coverage.test.ts` 通过。

## Acceptance Criteria

- [ ] 单测：摘要生成只含标题 / 名称 / 计数（不含路径、剪贴板正文）；推送项优先级与上限；剪贴板密钥项与超时项被跳过；无历史走引导卡、有历史走推送、推送为空退回引导卡。
- [ ] 单测：开场白状态机——首 token 前骨架；2.5s 后模板顶着、完整开场白整段替换；30s 到期 / 无提供方 / 失败 → 模板且不再替换；10 分钟同摘要复用；发送时生成中则取消且不并入；调用带输入框的路由、不带推理强度。
- [ ] 单测：`toProviderMessages` 把首条用户消息之前的助理消息转成系统提示；标题生成跳过开场白。
- [ ] 真实应用走查（CDP，带调试端口的 dev）：
  - 有历史、在 talex-touch 项目新对话：开场白提到 talex-touch 里的真实对话 / 会话，「为你准备」第一项与该项目相关；
  - 断网或选一个不可用路由：2.5 秒内出现模板开场白，没有报错；
  - 点一个推送项 / 引导卡起手任务：输入框出现任务文案并分裂发送，对话第一条是开场白、第二条是你的消息；重新加载该对话后顺序不变，继续聊时模型知道开场白说了什么；
  - 亮 / 暗主题、600px 高窗口各截图一张，布局不溢出、不跳动。
- [ ] core-app 包内 eslint、prettier、`vue-tsc -p tsconfig.web.json --composite false` 通过。

## 不做

- 不接日历、待办、下载目录等目前没有接口的数据源（「下载目录新文件」需要新的主进程接口，另立任务）。
- 不做后台定时推送 / 系统通知，只在打开新对话时推送。
- 不做「不再提示」开关；推送与开场白在每个新对话都出现（成本由 10 分钟复用控制）。
