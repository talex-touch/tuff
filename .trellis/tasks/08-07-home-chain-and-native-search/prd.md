# 首页对话：思考块分段与原生联网搜索

## Goal

一次用户反馈里包含两个可独立验收的交付：修正首页对话消息体的渲染结构，以及补上缺失的联网搜索能力。父任务只负责需求源、任务映射和跨子任务验收，不承担直接实现。

## 需求来源

用户对首页对话截图提出三点：

1. **「这个消息 tool 不能全都加到思考过程里吧」** —— 整轮的工具调用被无差别折叠进单个「思考过程」块。
2. **「我先思考 然后吐字 有思考 应该是有两个思考才对」** —— 思考块应当反映真实的流结构，而非把整轮拍平成一块。
3. **「原生应该是有搜索的吧」**（并以 codex 自带搜索为例）—— 助手回答「当前没有可用的联网搜索工具」不可接受。

## 任务映射

| 子任务 | 交付 | 状态 |
|---|---|---|
| `08-07-chat-stream-order-render` | 消息体按流顺序渲染：思考块只含 reasoning，工具作为独立卡片 | 可独立验收，无外部阻塞 |
| `08-07-native-web-search` | 首页对话具备联网搜索能力 | **阻塞：路线需用户裁决**，见该任务 prd.md 与 research/ |

两个子任务无实现依赖，可并行推进。子任务 2 的阻塞不得延迟子任务 1。

## 跨子任务验收

- [ ] 两个子任务各自的验收标准全部达成
- [ ] 复现截图场景：提出一个需要联网事实的问题，助手不再出现「整轮工具塞进一个思考块」的版式，且不再因无搜索能力而退化为凭记忆作答
- [ ] `pnpm lint` 与受影响包的 typecheck 通过（CoreApp 用包内配置，判 delta 不判零）

## 约束

- 用户已明确选定：工具**完全移出**思考块。2026-08-08 进一步要求升级为方案 C —— 正文一并按流顺序分段，不再在底部合并。
- 用户已明确选定搜索路线为「provider 自带 server-side search」。该选择在当前运行时下不可直接落地，冲突已记录在子任务 2，**须回到用户裁决，不得自行替换为其它路线**。
