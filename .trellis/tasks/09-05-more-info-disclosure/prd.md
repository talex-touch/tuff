# C4 · 更多信息折叠区

父任务：`09-05-clipboard-history-detail-relayout`。设计稿：pen 画板 `EQvwb`（S4 展开态），各屏底部的折叠条。

## Goal

用户原话：「右侧信息太密了 部分可以收纳到一个高级选项里」。

## 依赖与顺序

**依赖 C1**：需要重排后的 `.info-surface` 结构（`.summary-strip` / `.source-row` / 洞察容器）。C1 合入后开工。

## Requirements

### R1 折叠条

详情区最后一行常驻一条 disclosure：

```
›  更多信息                       MIME · Bundle ID · 完整调色板 · 原图路径
```

右侧摘要**按内容类型动态列出折叠区里实际有什么**，让用户不展开也知道里面装了什么。各类型的摘要文案：

| 类型 | 摘要 |
| --- | --- |
| 链接文本 | `MIME · 原始文本 · 字符拆分 · 记录 ID` |
| 图片 | `MIME · Bundle ID · 完整调色板 · 原图路径` |
| 文件 | `MIME · Bundle ID · 逐个文件大小 · 记录 ID` |
| 颜色 | `MIME · 原始文本 · 相近色 · 记录 ID` |

### R2 折叠区内容

展开后是一组 key-value 行（每行右侧一个复制按钮）+ 若干子分区：

- KV：`MIME` / `Bundle ID` / `记录时间`（完整时间戳，非摘要条的 `09/05 03:49`）/ `记录 ID` / `原图路径`
- 子分区「颜色」：完整调色板（超出摘要条展示范围的部分）
- 子分区「字符拆分」：完整字符网格 —— 摘要条与洞察区都不再承担这件事，**这里是它唯一的去处**

### R3 折叠状态持久化

- 默认收起。
- 展开/收起状态记忆到插件本地存储（`plugin:storage:set-file`），跨会话保持；不写数据库。
- 状态是**全局一个**，不是 per-item：用户展开过一次就说明想一直看到。

### R4 与摘要条的分工

摘要条只留 `类型徽章 + MIME + 尺寸/字符数 + 行数 + 时间`；`Bundle ID`、完整时间戳、记录 ID 一律下沉到折叠区。来源应用行只显示应用名，bundle id 作为次要行保留在来源行内（它是识别来源的关键，不下沉）。

## Acceptance Criteria

- [ ] 详情区末尾常驻折叠条，默认收起，右侧摘要文案随内容类型变化。
- [ ] 展开后可见 KV 行 + 颜色 / 字符拆分子分区；每个 KV 行可单独复制。
- [ ] 展开状态在插件重新打开后保持。
- [ ] 收起状态下，详情区的可见信息条数比重排前减少（重排前：eyebrow + 标题 + 5 行元信息 + 拆词统计；重排后：摘要条 1 行 + 来源 1 行 + 1 个洞察分区）。
- [ ] 折叠区展开导致内容超出可用高度时，`.info-surface` 自身滚动，不撑破面板。
