# C5 · 文件预览

父任务：`09-05-clipboard-history-detail-relayout`。设计稿：pen 画板 `C4UKRy`（S6 Markdown 渲染态）、`BJVC1`（S7 3D 模型）、SPEC 面板「文件预览（点击 👁 之后）」「预览的安全边界」两节。

## Goal

用户原话：「这种点击之后的预览呢？」「文本还要自动识别 代码（自动高亮）markdown 等等 尽可能多 还有 3d 建模的」。

C1 在文件树的每一行放了 👁 按钮，本任务实现点击之后的预览。

## ⚠️ 前置结论：这件事今天做不到，必须先加一个主进程能力

已核实（不是推测）：

1. `tfile:` 协议的可读根由 `apps/core-app/src/main/utils/local-file-policy.ts` 的 `getAllowedLocalFileRoots()` 决定，只放行：macOS 下 `~/Applications`、app-icon 缓存目录、`userData`、`temp`/`os.tmpdir()`、`/Applications`、`/System/Applications`、`/System/Library/CoreServices`。**`~/Downloads`、`~/Documents` 等一律不在内。**
2. 这不是疏漏，是 #914 的修复：该文件的注释写明，白名单曾经是整个 `app.getPath('home')`，导致任何渲染进程脚本可以 `fetch('tfile:///Users/victim/.ssh/id_rsa')` 并外传。收窄是有意为之，`local-file-policy.test.ts` 把这个行为钉住了。
3. 插件 SDK 没有通用文件读接口：`packages/utils/plugin/sdk/` 下 `clipboard.readFiles()` 返回的是剪贴板里的**路径**不是内容；`temp-files.ts` 只有 `create` / `delete`，不能读任意路径。

**因此本任务是五个子任务里唯一需要改主进程的**，父任务 `prd.md` 的「不改主进程」约束对 C5 不适用（已在父任务中标注例外）。

## Requirements

### R1 新增主进程能力（不得重开 #914）

```ts
// 主进程侧；渲染进程通过 transport 调用
previewClipboardFile(recordId: number, fileIndex: number, options?: {
  maxTextBytes?: number   // 默认 256 KB
}): Promise<ClipboardFilePreview>
```

四条硬约束：

1. **API 不接受路径参数。** 主进程用 `recordId` 从自己的剪贴板库里取出该记录的文件列表，用 `fileIndex` 取第 N 个路径。渲染进程无法指名任意文件 —— 这是本设计的全部安全性所在。
2. **只对存在的记录有效。** 记录被删除后该 `recordId` 立即失效。
3. **读取上限**：文本类取头部 256 KB（超出标注「已截断」），二进制类 20 MB，超限直接返回 `{ kind: 'too-large' }` 不读盘。
4. **挂独立权限位**，用户可在权限设置里单独关闭；关闭后 👁 按钮 disabled 并给出说明。

对应的负向测试（缺一不可）：
- 传一个不存在的 `recordId` → 拒绝，且不触碰文件系统
- `fileIndex` 越界 → 拒绝
- 记录里的路径被替换成 `~/.ssh/id_rsa`（构造一条这样的剪贴板记录）→ **允许**，因为用户确实复制了它；但这说明第 4 条权限位是真正的用户侧闸门，测试要断言权限关闭时被拒
- 20 MB + 1 字节的文件 → 返回 `too-large`，且 `fs.readFile` 未被调用

### R2 预览接管交互（S6 / S7）

- 点击文件行 = 选中（详情区元信息切到该文件）；点击 👁 = **预览接管整个预览区**。
- 顶部返回条：`‹` + 文件名 + 右侧 `类型 · 大小` + 「用默认应用打开」图标。
- `Esc` / `←` 退回文件树，回到原滚动位置与选中行。
- 预览区高度沿用 C1 的契约，`[data-kind='files']` 的 `max-height: 60%`；内容自身滚动。

### R3b 预览状态 · 10 态（矩阵见 pen 画板 M2 `j66oAS`）

**每一种类型都要覆盖这 10 态**，不是只做 happy path：

1. **未展开** — 文件行只显示 👁；不预读文件，不占内存
2. **加载中** — 骨架 + 已读/总字节；可取消。**超过 400 ms 才显示骨架**，避免闪烁
3. **加载完成** — 正常渲染；返回条显示 `类型 · 大小`
4. **部分加载** — 超过读取上限（文本 256 KB）：标注「仅显示前 256 KB」+ 用默认应用打开
5. **超大文件** — 二进制 > 20 MB：**不读盘**，只给元信息 + 打开；**在主进程拦，不能读完再判**
6. **空文件** — 0 字节：明说「文件为空」，不要显示空白面板
7. **解析失败** — 给出原因（编码错误 / 格式损坏 / 依赖缺失）+ 降级为纯文本或十六进制
8. **密码保护** — 加密 PDF / 加密 zip：输入密码；**密码不进日志、不落盘、只在内存存活到关闭预览**；连续 3 次错误后停止重试
9. **无权限** — 预览权限位被关闭：说明 + 一键去设置；不要静默失败
10. **文件已不存在** — 记录还在但文件被删/移动：提示 +「从记录中移除路径」；**不要伪装成加载失败**

对应设计稿：ST1 加载中 `DjWsZ`、ST2 超限截断 `fbKCy`、ST3 密码保护 `qOszR`、ST4 文件已不存在 `x7hWu`。

### R4 依赖成本（实现前必须先评估再动手）

- **语法高亮**：`shiki` 体积大但准确，`highlight.js` 轻但语言包要裁剪。**先量打包体积增量再选**，不要默认引全量语言包。
- **3D**：`three.js` + `GLTFLoader` / `STLLoader` / `OBJLoader`。这是本任务最重的一笔，**必须按需动态 import**，不能进主 bundle。P2 之前先确认懒加载确实生效。
- 插件有 100MB 存储上限但没有包体上限；即便如此，把一个启动器插件撑到几 MB 也不合理。
