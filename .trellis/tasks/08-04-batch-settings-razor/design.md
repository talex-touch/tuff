# 批量剃刀：设置收敛设计

## 决策目标

设置不是功能目录。每个可见控件必须代表用户可以安全、可逆且有意义地作出的选择；否则应用应采用明确的系统策略，或在真正需要时通过一个任务入口向用户请求授权。

## 处置模型

| 处置 | 适用条件 | UI 结果 | 配置结果 |
| --- | --- | --- | --- |
| 保留 | 改变反映长期个人工作偏好，且两种结果均受支持 | 一个清晰的用户控件 | 保持单一公开配置键 |
| 合并 | 多个控件共同表达一个高层意图 | 一个意图级入口或选择器 | 由域内策略派生细节 |
| 系统默认 | 安全、数据完整性、维护稳定性或隐私基线 | 不在设置页展示 | 不保留用户覆盖键 |
| 按需或高级入口 | 仅在执行特定动作时需要平台确认/一次性选择，或是低频但仍有真实个人偏好的细节 | 默认不占据常规设置；由用户主动打开的“高级设置”或动作/失败恢复流承载 | 平台授权、操作上下文或受限的偏好键为真相 |
| 仅开发者可见 | 诊断、实验、测试或环境切换 | 开发构建/明确高级入口 | 不属于普通用户设置模型 |
| 删除 | 无消费者、被新结构替代或与另一项重复 | 无入口 | 迁移后删除死配置 |

## 普通用户最终决策面

常规设置只保留以下决策；其余项目按盘点表处理为默认策略、按需任务、开发者工具或信息页。

| 决策面 | 用户能做的选择 | 不再单独出现的细项 |
| --- | --- | --- |
| 语言 | 选择显示语言，包含“跟随系统”值 | 单独的跟随系统开关 |
| 同步 | 是否授权本设备同步账户数据 | 同步状态、队列、重试和手动运维 |
| 启动与后台 | 是否开机启动、是否关闭后继续在后台运行 | Dock、托盘、静默启动和窗口实现细节 |
| 助手 | 是否启用助手；需要时进入语音设置流 | 悬浮球和唤醒词的无效组合、助手改名 |
| 网络 | 用户主动打开高级设置，或默认系统网络无法工作时配置代理 | 重试、超时、退避等传输参数 |
| 数据管理 | 打开独立的数据/隐私管理页 | 存储占用伪开关和普通设置页内的清理细节 |

## 高级设置边界

“高级设置”是用户主动打开的渐进披露层，不是旧设置页的收容箱。只有下列低频但仍属于个人偏好的项目可以进入：

| 高级域 | 可保留的详细选择 | 不得迁入的项目 |
| --- | --- | --- |
| 网络 | 手动代理模式、主机、端口、认证和 bypass | 重试、超时、退避、网络诊断原始信息 |
| 助手与输入 | 语音唤醒/唤醒词、悬浮入口、鼠标长按、自动粘贴与自动隐藏 | 助手品牌名称、内部轮询/清理/节能参数 |
| 个性化 | CoreBox 自定义占位文字、快捷键管理 | 推荐排序权重、来源数组和结果数量 |
| 来源恢复 | 书签或目录等需要用户授权的来源接入/重建 | 索引空闲阈值、充电策略、backfill/full-sync 调度 |

以下能力即使当前曾受 `advancedSettings` 控制，也不属于普通高级偏好：凭证保护、更新渠道与运行时覆盖、下载并发/分块、Everything 后端与 CLI、Sentry、开发模式、搜索日志和所有证据导出。它们分别是系统策略、故障恢复或开发者能力。

## 登录凭证保护

### 当前边界

- 认证 token 已由 `AuthModule` 通过 `secure-store.json` 管理。
- 实际后端是本地随机秘密派生的 AES-256-GCM 加密存储，不是 OS Keychain 或系统 root 密钥。
- `auth.useSecureStorage`、`auth.secureStorageUserOverridden`、`auth.secureStorageReminderShown` 与 `auth.secureStorageUnavailable` 是旧的“用户可关闭保护”模型遗留字段。

### 目标状态

```text
认证成功
  -> 仅尝试受保护持久化
  -> 成功：后续启动恢复登录态
  -> 失败或损坏：保留当次内存登录态，退出后重新登录

普通 app settings
  -> 不保存任何“关闭凭证保护”的覆盖状态

设置页
  -> 不渲染凭证保护开关、状态或错误行
```

### 兼容与迁移

1. 启动时无条件归一化历史 `useSecureStorage: false` 和用户覆盖标识为强制保护语义。
2. 移除切换处理器、关闭提醒、设置页健康查询，以及只为这些流程存在的 i18n 文案。
3. 若旧普通持久化位置含 token，迁移必须只向受保护存储写入；写入失败时删除或拒绝继续使用该普通持久化值，不得继续读取。
4. 健康检查仅供主进程诊断与日志使用。日志遵守现有敏感数据投影规则，不记录 token、密钥、路径或原始错误。
5. 更新 `sensitive-data-inventory.json` 中 `nexus-auth-session` 的存储、失效、迁移和证据声明；认证协议文档链接回该可执行库存。

## 非目标

- 本任务不把当前 `local-secret` 后端包装为系统 Keychain，也不虚构其硬件或 OS 保护能力。
- 是否改用系统凭证存储是独立安全架构任务，需要平台矩阵、迁移/回滚和真实设备验证。
- 不改变插件内部由插件业务拥有的配置，除非盘点证实其被错误暴露为全局设置。
