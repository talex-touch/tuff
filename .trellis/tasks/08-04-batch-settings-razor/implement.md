# 批量剃刀：实施计划

## 前置条件

- 用户审阅并确认完整设置清单与每项处置后，才执行 `task.py start`。
- 认证存储改动前，加载 CoreApp 的前端、主进程、类型安全和敏感数据生命周期规范。
- 落实前检查当前并行的设置 IA 改动，避免覆盖 `08-04-settings-ia-primitives` 的未提交文件。

## 执行顺序

1. 将盘点结果写入本任务的 PRD；确认每个普通设置控件都有唯一处置，并识别共享配置键的唯一拥有者。
2. 实现认证强制保护：移除用户覆盖分支和 UI 控件；将旧配置归一化；受保护存储失败时只保留进程内登录态。
3. 更新或添加认证模块和设置页的聚焦测试，覆盖旧的“关闭保护”配置、存储不可用、登出和冷启动恢复边界。
4. 按经确认的清单逐批实施设置项收敛。先建立用户主动进入的高级设置边界，再按域迁移低频个人偏好；每一批只处理相互关联的一个设置域，完成后验证相应平台/配置迁移。
5. 对安全、稳定性、资源调度、更新运维和开发诊断项实施系统默认或开发者隔离，不得因为“高级设置”存在而保留普通用户覆盖键。
6. 在 `docs/engineering/sensitive-data-inventory.json` 和其关联工程文档中记录认证凭证实际存储、迁移、失效与不可导出契约；更新其验证证据。
7. 删除废弃配置键、UI/i18n 文案和无消费者测试；保留明确的配置迁移或兼容读取，直到其数据迁移窗口结束。

## 认证验证

- `apps/core-app/src/main/modules/auth/index.test.ts`：旧用户关闭偏好不能恢复未保护持久化；安全存储可用时冷启动恢复；不可用时退出后需重新登录。
- `apps/core-app/src/main/utils/secure-store.test.ts`：保持加密、权限、原子写入和不可用行为的既有安全契约。
- `apps/core-app/src/renderer/src/views/base/settings/SettingUser.*.test.ts`：设置页不再渲染凭证保护选项或它的状态文案。
- `corepack pnpm privacy:inventory:verify`：库存与认证生命周期声明一致。
- CoreApp Node/Web typecheck、相关 Vitest、scoped lint 与 `git diff --check`。

## 回滚边界

- 设置 UI 的单项收敛可按域独立回滚；不得回滚至允许普通持久化登录 token 的认证路径。
- 若强制保护迁移发现真实用户配置或跨平台兼容问题，保留仅会话模式并停止持久化迁移；不要重新暴露关闭保护的开关。
- 若需要改变 `local-secret` 的物理密钥后端，另建安全架构任务，提供跨平台迁移、现有密文兼容和真实设备证据。
