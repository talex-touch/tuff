# 批量剃刀：收敛设置选项

## Goal

以“默认替用户决定、仅在行为确有个人偏好或需要显式授权时才保留选择”为原则，盘点并收敛 Core App 的所有面向用户的设置项，降低设置页的决策负担。

## Confirmed Constraints

- “登录凭证保护”是设备级安全基线：每台设备必须启用，用户不能关闭。
- 设置页不得显示该能力的开关、状态行、不可用提示或其他只读呈现。
- 该安全能力的目的、适用条件、后端降级策略与准确的实现术语，必须在相关协议和开发文档中说明；不依赖 UI 文案进行解释。
- 安全存储无法创建、读取或校验时，只允许当次进程持有登录态；退出后必须重新登录，绝不降级为普通配置持久化。
- 盘点范围覆盖所有现有设置路由、其内嵌的设置组件及影响同一配置键的重复入口；所有普通用户开关和当前高级设置中的普通用户开关均纳入本轮分类。插件自身的业务配置不在本轮直接重设计，除非其被错误地放入全局设置。
- 设置采用渐进披露：仅有低频且仍反映个人使用方式的项目可迁入用户主动打开的“高级设置”；安全基线、稳定性/资源调度策略、诊断与开发能力不因此重新成为用户开关。
- 当前只进入规划；在用户审阅并批准规划产物前，不修改产品代码或配置。

## Requirements

- 为每一个当前可见的用户选项列出：所在页面、配置或平台能力、实际消费者、是否为跨平台项，以及建议处置。
- 每项处置只能是：保留为用户偏好、合并到更高层意图、改为系统默认、迁移到按需或高级入口、仅开发者可见，或删除。
- 用户偏好仅在其关闭或改变确实会反映个人使用方式时保留；安全、稳定性、维护与默认隐私基线不得作为普通开关暴露。
- 相同配置键的多个入口必须统一为一个明确的用户决策点，或全部移除为系统策略。
- 输出实施顺序、迁移策略和回归验证范围，确保既有本地配置不会造成保护降级或错误 UI。

## Acceptance Criteria

- [ ] 完成设置选项清单，包含精确的代码位置和配置/能力归属。
- [ ] 每项均有唯一的“保留、合并、默认、迁移、开发者可见、删除”处置建议及依据。
- [ ] “登录凭证保护”方案明确移除用户可覆盖的状态与 UI，定义旧配置的迁移行为、失效时的仅会话策略及非 UI 协议文档落点。
- [ ] `prd.md`、`design.md`、`implement.md` 和盘点研究记录说明范围、依赖、风险、验证与回滚策略。
- [ ] 凭证保护的工程契约更新 `docs/engineering/sensitive-data-inventory.json` 和 `.trellis/spec/frontend/privacy-data-lifecycle.md`；两处均准确描述实际后端、不可导出性和仅会话失效策略。
- [ ] 用户审阅规划产物后，才可执行 `task.py start` 并进入实现。
