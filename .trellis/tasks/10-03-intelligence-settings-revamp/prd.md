老板在真机（v2.4.14-beta.56）走查「塔芙智能」设置区时，用截图批注提了一批改动；同时问到「本机装的 pi / omp / claude / codex 似乎拿不到」。两件事一起规划，按页拆成子任务，各自独立验收后交付。

## 已确认的决策（2026-10-03）

- 建父任务，按页拆成子任务，先规划再动手。
- 「通用」就是本机 skills：「通用技能」组排在第一，原来的 31 项归入「内置技能」。「能力」一律改叫「技能 Skills」，侧栏同步改。
- 底部提示条采用**手动保存**：改动先暂存，点「保存」才写入，离开页面前提醒。
- 探测问题一起修，并**去掉 `TUFF_ENABLE_LOCAL_AI_CLI` 环境变量门槛**：macOS 上本机代理功能直接可见。
- **产品定位（硬约束，适用于全部子任务）**：Tuff 只**复用**本机 CLI（pi / omp / codex / claude…）的凭证，并顺带**调用**它们，不做 cc-switch 那种管理器或代理。具体来说：
  - 不往任何代理目录里写入、链接或同步技能和配置；
  - 不改写 CLI 自己的配置文件；
  - 不替 CLI 切换 provider。

  技能、MCP 的「本机发现」都是只读的；开关只影响 Tuff 自己。

## 子任务

| 子任务 | 交付 |
|---|---|
| `10-03-mcp-settings-page` | MCP 独立成页，侧栏排在「技能」下方 |
| `10-03-skills-page-revamp` | 能力页改版为技能页：通用技能 / 内置技能、代理归属、留白、手动保存 |
| `10-03-nexus-channel-copy` | 模型渠道 Tuff Nexus 详情的标签与文案 |
| `10-03-local-agent-detection` | 本机代理 CLI 探测修复、去门槛、MCP 发现缺口 |

执行顺序：`nexus-channel-copy`、`local-agent-detection` 与其余子任务互不依赖，可以随时做。`mcp-settings-page` 必须在 `skills-page-revamp` **之前**，因为两者都要拆 `SettingSkillsMcp.vue`：MCP 先拆走两组，技能页再接走剩下的技能部分，然后删除这个文件。

两条跨任务的数据依赖：
- MCP 页发现行的名字（「Codex MCP」「Oh My Pi MCP」「Pi MCP」）由 `local-agent-detection` 提供，MCP 页只按 `candidate.name` 渲染。
- 侧栏「技能」的叫法由 `skills-page-revamp` 改，在那之前 MCP 项排在「能力」下方，位置不变。
