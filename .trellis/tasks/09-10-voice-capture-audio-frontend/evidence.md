# Evidence：语音采集前端链路

测量日期 2026-09-10，机器 macOS 26 (Darwin 25.5.0)，设备 "MacBook Pro Microphone"。

## 1. D2 的真机证据：旧固定阈值在本机就是坏的

PRD 起草时把「底噪高于阈值导致尾静音自停永不触发」列为**代码推导、未实测**。
现已在真机测到，结论比推导更强。

安静房间、无人说话，`noiseSuppression: false`，采样 16 kHz，10 ms 窗：

| 指标 | 实测 |
|---|---|
| 底噪 min / median / max | −180.0 / **−43.7** / −32.2 dBFS |
| 旧阈值 `SILENCE_RMS_THRESHOLD = 0.01` | −40.0 dBFS |
| 4 s 内超过旧阈值的窗数 | **68 / 373（18.2%）** |

5.76 s 的第二次采集进一步确认：

| 指标 | 实测 |
|---|---|
| 超过旧阈值的窗数 | 125 |
| **相邻超阈窗之间的最大安静间隔** | **500 ms** |
| 尾静音自停所需 | 1500 ms |

**结论**：本机房间底噪中位数只比旧阈值低 3.7 dB，18% 的窗直接超阈。超阈窗之间
最大只安静 500 ms，永远到不了 1500 ms，因此 `last_sound_ms` 被持续刷新，
**尾静音自停在本机从未触发过**——每次听写都只能跑满 15 s 上限或手动停。

这不是边界情况，是这台机器上的默认行为。

## 4. R3 自适应静音判定：工作区间（自动化，5 组种子）

语音 −18 dBFS，合成带噪流：

| 底噪 | SNR | 检出 | 自停 |
|---|---|---|---|
| −60 ~ −22 dBFS | 42 ~ 4 dB | 5/5 | 5/5 |
| −18 dBFS | 0 dB | 0/5 | 0/5 |

负控制（必须全 0）：纯噪声 −60/−40/−30/−22/−14 dBFS 全部 0/5；全零数字静音不检出。
0 dB SNR 检不出是接受范围——那个信噪比下 ASR 本身也没有可用输出。

阈值选择留档：ENTER=4.0 与 3.0 在 4 dB SNR 场景漏检；2.5/1.6 与 2.0/1.4 全通过；
取 2.5（+8 dB 进入 / +4 dB 退出）。10 ms 窗 RMS 的相对标准差约 5%，
+8 dB 距高斯噪声的自然起伏有 20+ sigma 余量。

## 5. F1 谱降噪：分噪声类型的实际效果（自动化）

| 噪声类型 | 降噪量 |
|---|---|
| 风扇类低频噪声（900 Hz 以下） | **58.5 dB** |
| 白噪声 −30 dBFS | 4.0 dB |
| 工频嗡声 120 Hz + 谐波 | 2.6 dB |
| 白噪声 −45 dBFS | 0.4 dB |

真机同一房间背靠背对比（无刻意说话）：

| | 底噪 | 时长 |
|---|---|---|
| 降噪关 | −40.64 dBFS | 2730 ms |
| 降噪开 | −46.36 dBFS | 2900 ms |
| **差** | **−5.73 dB** | +170 ms（两次采集的设备启动延迟差，非降噪造成的丢帧） |

RNNoise 对**低频稳态噪声**极强，对宽带嘶声弱。这正好对上用户实际抱怨的对象
（风扇、空调），也解释了为什么它值得存在但不值得默认开启。

## 6. 真机端到端冒烟

release addon 重建、ad-hoc 签名、headless 加载通过。真实麦克风采集：

```
support: {"supported":true,"platform":"macos"}
started with suppression, device = "MacBook Pro Microphone"
stopped: wav 16000Hz 1ch 660ms reason=max-duration bytes=21164
```

字节数校验：660 ms × 16000 Hz × 2 B + 44 B 头 = 21164 ✓

addon 体积：2,726,192 → 3,400,800 B（**+674,608 B，+24.7%**），来自
nnnoiseless 内置模型与 rustfft。

## 7. 未完成：AC10 识别率 A/B

**没有做。** 识别率对比需要用真实 ASR provider 跑两次付费请求，
且需要一段真实带噪人声录音。本次未调用任何 provider，也未产生任何识别文本。

因此**「降噪对识别率的净影响」仍然未知**，`noiseSuppression` 保持默认关闭——
这个默认值目前由技术判断支撑，不由本机数据支撑。要改默认值，必须先补这一步。

上面第 5 节的 dB 数字只证明降噪器在做它声称的事，**不证明识别更准**。
